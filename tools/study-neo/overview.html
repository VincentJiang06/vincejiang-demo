从一个 Linux 命令读懂课程路线

你写了一个把数字 3 打到屏幕上的小程序。源码、可执行文件和正在运行的程序分别在哪里？

终端是输入命令、看到输出的窗口，shell 在窗口里解释你输入的命令。在已经装有 C 编译器的 Linux 环境里输入 pwd，回车后会显示当前目录的路径；再输入 ls，列出这个目录里的文件。打开文本编辑器，把下面两行存为当前目录里的 count.c。第一行引入输出函数的声明，第二行定义程序入口 main，其中 printf 打印 3 并换行，return 0 表示正常结束。

在同一目录的终端输入 cc -Wall count.c -o count。cc 启动编译和链接，-Wall 开启一组常见警告，-o 指定输出文件名。成功后输入 ./count，./ 要求 shell 在当前目录找可执行文件，屏幕会出现 3。再执行一次，会从同一可执行文件启动新的进程。用虚拟机练习时，宿主系统运行虚拟机软件，客体 Linux 运行自己的内核。这里的命令和路径都在客体中解释。

沿着这次运行追问：程序如何请求内核？保存的文件怎样变成设备上的块？谁在众多程序之间分配 CPU、内存？若改成两条线程一起数，谁负责保护共享变量？这依次通向系统调用、持久化、虚拟化和并发。

一条加法指令怎样运行？

设内存地址 40 放着一条“把寄存器 R 加 3”的指令，初始 R=5。按下运行之后谁读它？

磁盘上的程序保存代码与静态数据。装载器为进程建立地址空间，安排代码、静态数据、供动态对象使用的堆、供函数调用使用的栈。CPU 从内存取得下一条指令。冯·诺依曼模型让指令与普通数据都可存放在内存，通过总线在处理器与内存间传送。

程序计数器 PC 给出下一条待取指令的位置；取来的指令进入指令寄存器 IR。控制单元译码决定数据从哪里来，算术逻辑单元 ALU 完成加法等运算，通用寄存器短暂保存操作数和结果。状态寄存器保存条件标志等信息，后续条件分支可以利用这些标志。

自己试一次

若 CPU 已取出并执行地址 44 处的无条件跳转，目标为 96，随后从何处取指？

核对推导

A · 无条件跳转把目标地址交给 PC。取指位置由 PC 决定，加法留下的 R=8 不参与这个决定。

为什么应用要向内核请求服务？

一个文本编辑器要保存文件，同时另一个进程正读取同一块磁盘。若两个程序都能随意操作设备，会发生什么？

操作系统管理 CPU、物理内存和 I/O 设备，并把资源包装成应用可用的抽象。进程获得可继续执行的指令流、独立的地址空间和可按名字访问的文件。内核是能执行特权操作的部分。应用通过系统调用（system call）给出请求和参数，内核检查访问权、协调共享资源、返回结果或错误。

以保存为例，编辑器给 write 一个已打开的文件描述符、缓冲区和字节数。内核检查描述符是否可写，随后把数据交给文件系统。普通的整数加法只需要 CPU 指令；许多 C 库函数也无需每次进入内核。设计这些边界时还要衡量软件开销、失效后的恢复、不同进程间的保护、能耗及安全性。课程把移动性也列为设计考虑，例如移动设备需要在省电与及时处理输入之间权衡。

自己试一次

排序函数比较两个已在内存中的整数，通常需要哪项操作？

核对推导

B · 比较只访问寄存器或进程有权访问的内存。在页已驻留等正常条件下，程序无需为该比较主动调用内核。

一个核心怎样让两个进程都前进？

在只有一个核心的机器上，两个程序各打印一个不同的字母，终端却出现交错的两种字母。

分时的基本动作是先暂停 A，保存其程序计数器、寄存器等上下文，再恢复 B 先前保存的上下文。以后恢复 A 时，它从暂停点继续。内核调度器选择下一位运行者，时间片到期或程序阻塞都可能触发切换。

并发表示两段工作的生命周期重叠，都能取得进展；单个核心在这个模型中每一时刻只为一个进程执行指令。在两个核心上两者还可能并行。终端上字母的先后能展示交错，却不能单凭这串字母反推核心数量或唯一调度顺序。

两个进程中相同的地址指向哪里？

甲乙各显示“我的整数位于地址 0x1000”，随后甲把整数改为 9。乙会读到什么？

一位（bit）只有 0、1 两种取值，本书的机器用 8 位组成一字节（B），每个字节有一个地址。1 KiB 是 1024 B；1 MiB 是 1024 KiB，1 GiB 是 1024 MiB。前缀 0x 表示十六进制，每一位十六进制数恰好表示四个二进制位，所以 0x10 等于十进制 16。

内存可以想成按字节编号的大数组。load 从地址取值，store 把值写到地址。程序中显示的地址通常是虚拟地址，其含义依赖当前进程的地址空间。内核设置映射，硬件据此找到物理内存中的实际位置。

假设两个进程各有一个私有变量，初值为 2。它们可以使用相同的虚拟地址，对应不同物理位置；甲的 store 只会改变甲映射到的位置。地址空间随机化也可能让同一程序两次显示不同地址。显式共享的映射则可以让多个进程访问同一份数据。

自己试一次

两个进程都成功从同一个虚拟地址读出数值 2，能否证明这两次读取访问同一物理单元？

核对推导

A · 两个私有单元完全可以具有同样的值。要证明共享，需要知道两个地址是否映射到同一物理位置。

两次加一为什么可能只多一？

音乐播放器有两条线程，各给共享计数器加一。初始为 7，先按一台只有一颗核心的小机器来推演。

线程各有自己的控制流、程序计数器和寄存器，但同一进程中的线程可以读写同一个全局变量。把加一分解成三条简化指令：从共享内存装入本线程的寄存器、寄存器加一、写回共享内存。只有第三步才改变其他线程随后能读到的值。

假设第一条线程完成加法后被时钟中断。内核保存它的寄存器和下一条指令的位置，再恢复第二条线程。第二条线程完成整次加法后，第一条仍会继续执行自己的写回；上下文保存得完全正确，过期的数值也因此被完整保留下来。

再想一步

这是为理解交错而规定的指令级模型。在 C 中，多个线程无同步地读写同一普通整数且至少一方写入，构成数据竞争，语言行为未定义。volatile 不能代替同步。

主线程等两名工作线程都结束（join）之后才显示计数。这一个改变能排除丢失更新吗？

一次“保存”穿过哪些层？

程序刚显示“保存成功”，用户就断了电。下次开机，磁盘上的字节究竟取决于什么？

DRAM 是易失存储，掉电后内容会丢失。磁盘和 SSD 提供非易失存储。文件系统用普通文件存放应用字节，用目录联系名字与对象，一些设备还能通过特殊文件访问。应用打开名字获得文件描述符，写入字节，再关闭描述符。

内核需要决定数据放在哪个块、文件有多长、目录名指向哪个对象，再安排设备请求。write 成功通常意味着内核已经接收了数据。若要在返回之后承诺持久化，要同步文件，并在涉及新建或改名时考虑目录。许多文件系统用日志或写时复制维护崩溃后的结构一致性，这与某个应用指定的保存时机是两个问题。

自己试一次

内核刚在内存里接收了新内容，设备尚未写入，此时掉电会怎样？

核对推导

B · 易失缓存里的修改尚无持久副本。下次启动可见的状态取决于此前已落盘的数据与文件系统的恢复协议。

改了源码，为什么屏幕上还是旧数字？

你把源文件里输出的 6 改成 9，只保存，然后再次执行原目录里的 ./calc。运行前可执行文件还没被替换。屏幕该显示什么？

展开推导
  1. 磁盘上有两份不同的对象：供人修改的源文件、供系统装入的可执行文件。保存动作只更新前者。
  2. 启动 ./calc 时，装入器读取仍含旧逻辑的可执行文件，因此这次仍输出 6。
  3. 重新编译并链接成功后，再次启动才会输出 9。
