CPU 到设备之间经过什么？

插上一块 USB 存储，CPU 怎样才能和设备说同一种“语言”？

总线是一条在硬件部件之间传递地址、数据和控制信息的通道。在简化的分层图中，CPU 经内存总线访问主存，高带宽的一般 I/O 互连可连接图形等设备，外围总线或接口再接存储和其他外设。PCI、SATA、USB 等服务的设备、带宽与连接要求不同，具体机器布线会变化。

设备控制器对外暴露硬件接口，内部可以有微控制器、DRAM 或 SRAM 和专用芯片。驱动通过端口或映射地址访问设备的寄存器。知道这些寄存器的含义即可发命令，驱动无须操纵控制器内部的每个电路。

自己试一次

两种控制器内部芯片不同，都能接受同一种块请求。通用文件系统首先需要依赖哪一层？

核对推导

A · 上层可用共同语义描述请求，具体寄存器协议由相应驱动转换。

如何和只提供几个寄存器的设备交谈？

一台标签打印设备要接收一个字节，再执行打印。驱动需要区分“可接收”“传入的数据”和“立即开始”。

状态寄存器（status）报告忙、就绪或出错等条件；数据寄存器（data）用于传入或取回数据；命令寄存器（command）指定设备要做的动作。寄存器由设备解释，对同一个地址读和写甚至可能有不同语义。必须按该设备的协议操作。

先确认设备可接受参数，再写数据，然后写命令启动，最后等待完成并检查结果。在端口映射方案中，x86 用 in/out 等专门指令访问 I/O 端口。内存映射 I/O（MMIO）把寄存器安排在地址空间里，内核可通过合适的 load/store 和平台 I/O 访问原语操作它；这些地址对应硬件而非普通 RAM。

自己试一次

把设备寄存器映射到一个地址后，向该地址 store 的效果是什么？

核对推导

A · 地址译码把该范围交给设备。写入是否启动命令、交付数据或设置标志，由对应寄存器决定。

用轮询还是中断等完成？

一次磁盘读取要等很久，CPU 还有别的工作。一旦提交请求，CPU 用这段时间做什么？

轮询（polling）由 CPU 重复读取状态寄存器，直到条件满足。控制流简单，完成时能很快发现，但轮询的时间无法同时拿去运行其他任务。中断（interrupt）由设备向处理器报告事件；内核可以先阻塞等待者，调度另一项工作，到中断时运行处理程序、确认完成并唤醒等待者。被唤醒表示重新具备运行资格。

哪种方式更省 CPU 取决于等待时长、检测延迟、是否有其他就绪任务，以及进入处理程序和调度的开销。假设一次中断路径共用 4 微秒 CPU，忙等 1 微秒可更便宜；若设备需 100 微秒，就能让大部分时间用于别的工作。真实系统还可先短暂轮询再睡眠。

自己试一次

一个设备固定在约 1 微秒内完成，而睡眠、唤醒和中断处理需要 5 微秒 CPU。仅比较此次 CPU 开销，哪种更合适？

核对推导

C · 设定中轮询只需约 1 微秒，低于完整中断路径的 5 微秒；延迟、能耗或并发需求变化时要重新比较。

中断解决了等待，谁来搬运大块数据？

控制器已经愿意接收一张图的 64 KiB。CPU 是否还要亲自把每个字搬给设备？

程序控制 I/O（PIO）由 CPU 执行读写，逐段把数据在内存与设备之间传送，字数越多越占用 CPU。DMA（直接内存访问）让 DMA 引擎或具备总线主控能力的设备按驱动设置的地址、长度、方向传输。CPU 仍负责建立请求、准备设备可访问的缓冲区并检查完成。

例如 64 KiB＝65536 字节，按每次 4 字节的简化 PIO 循环需搬 16384 次。DMA 把这些数据移动操作交给硬件，CPU 在传输期间可以处理其他进程。内存与互连带宽仍然会被消耗。传输结束后的通知能用中断；缓冲区转交、介质写完、数据跨掉电持久是可能不同的时刻。

自己试一次

设备采用 DMA 搬运，并由驱动轮询完成位，这在概念上可能吗？

核对推导

A · DMA 描述搬运主体。驱动如何获知 DMA 完成取决于设备支持和策略，可以是轮询。

为何文件系统无需认识每一种硬盘？

同一段读文件代码运行在使用两种不同存储控制器的机器上。到底是谁把一次 read 翻译成设备命令？

应用提交 POSIX 风格的 open/read/write/close。文件系统解释目录、inode 和文件偏移，把文件的逻辑范围转成逻辑块请求。通用块层整理请求，具体设备驱动再把“读这些块”翻译为 SCSI、ATA 等控制器能执行的协议。设备完成后，结果沿相反方向交回上层。

接口使新型号设备可以接入既有文件系统；代价是如果通用接口没有表达某种专用功能，普通请求通常用不到它。驱动需要处理不同设备的状态、错误、并发和完成顺序。运行在内核里的驱动若有错误，也可能影响整个系统的可靠性。

自己试一次

哪个层次最适合决定“某个 inode 的逻辑块 4 对应卷上的块 91”？

核对推导

A · 该映射由文件系统的索引布局给出。设备驱动接到的是已经转换成块范围的请求。

怎样读懂传统 IDE 的一次扇区请求？

简化 IDE 控制器要从第二个驱动器读取 LBA 0x0123456 的一个扇区。一个块号如何被写进几个短寄存器？

LBA 是逻辑块地址。传统 IDE 的示例端口中，0x1F2 接收扇区数，0x1F3、0x1F4、0x1F5 接收 LBA 的低、中、高三个字节；0x1F6 还携带高四位、设备选择及 LBA 模式。0x1F7 写入时是命令、读取时是状态；0x1F0 传数据，0x1F1 可读错误细节，设备控制寄存器在 0x3F6 可用于控制复位和中断屏蔽。

等待时须符合协议，如 BSY 清零且 DRDY 置位。发读写命令后，数据阶段看 DRQ；写入时主机在设备要求数据后通过数据口发送，读出时等待数据就绪并读取。若状态中 ERR 置位，再读错误寄存器辨别 ABRT（命令中止）、UNC（不能纠正的数据错误）等。DF 表示设备故障。一个操作也可能需要多次中断。例如状态字是 0x48（二进制 01001000），位 7 的 BSY 为 0，位 6 的 DRDY 为 1，位 3 的 DRQ 为 1，位 0 的 ERR 为 0。处于这一数据阶段时，主机按已发命令的方向传输数据。

再想一步

状态字的常见布局从高到低为 BSY、DRDY、DF、DSC、DRQ、CORR、IDX、ERR；历史设备还以 BBK、UNC、MC、IDNF、MCR、ABRT、TK0NF、AMNF 等位报告具体错误。应按目标设备版本解释。 示例驱动对 0x3F6 写 0，使屏蔽位 nIEN 清零、允许设备发完成中断。写这个控制口本身并不代表本次请求已经完成。

自己试一次

对 LBA 0x0AB12CD，送到 0x1F4 的中间字节是什么？

核对推导

B · 从右边每两位十六进制数字一组：CD、12、AB。第二组 12 就是 (LBA >> 8) 的低八位。

驱动怎样让排队、睡眠和完成配对？

甲提交读取扇区 A，乙紧接着提交写入扇区 B。简化 IDE 驱动一次只能处理队首。谁唤醒甲，又是谁开始乙的请求？

每个缓冲对象记录目标扇区、数据、队列链接以及状态。VALID 表示缓冲中有有效内容，DIRTY 表示内存中有待写出的修改。用锁保护请求队列和状态。提交者入队，若成为队首便启动设备；如果请求尚未完成就用能原子释放锁并等待的睡眠操作，醒来后重新取得锁并再检查条件。在代码里，这段入口叫 ide_rw；它在已有队首时只追加请求，第一项才调用 ide_start_request。

处理程序从设备得到中断，找回当前队首并检查设备状态。成功读需把设备数据取入该缓冲，成功写则确认先前提交完成。设置 VALID、清除 DIRTY、唤醒等待该缓冲的进程，移走队首并启动下一个。实际驱动还须把错误送回调用者，不能把失败当成有效数据。对应的完成入口叫 ide_intr。以一个 512 字节扇区为例，若端口一次传 4 字节，读数据的 insl 或写数据的 outsl 分段共传 128 个四字节单位。

自己试一次

甲尚未睡下时设备就完成，会不会必然丢通知？哪种设计能正确处理这种时序？

核对推导

B · 若完成先发生，甲检查即见谓词已满足；若甲先等待，能原子释放锁的等待机制让中断处理方更新状态并唤醒它。

条件迁移 · 自编题

CPU 忙于搬数据，还是忙于等设备？

某设备每次准备 8 个字，每个字都要写入主存。把按状态位轮询改为中断通知后，缓冲区仍由驱动逐字读取端口。CPU 是否免除了 8 次搬运？

展开推导
  1. 通知方式决定处理器怎样得知就绪。中断让处理器不必一直检查状态位。
  2. 这个设计仍要求驱动读端口并写内存，因此每个字的搬运仍要 CPU 参与。
  3. 若控制器与平台支持 DMA，可另行配置内存位置和长度，由 DMA 传输；完成时仍可发中断。

设备协议迁移练习，状态与传输长度自编。
