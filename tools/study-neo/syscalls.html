怎样辨认正在运行的是谁？

同一用户从终端启动两次播放器。磁盘上只有一份程序，系统怎样分别管理两次运行？

程序是静态的代码和初始数据。进程是一次执行，内核为它维护标识、执行上下文、地址空间和打开的资源，线程携带一条实际推进的指令流。进程被创建时形成父子关系；父进程可以创建多个子进程。

PID 在同一 PID 命名空间中标识当前这个进程，PPID 记录当前父进程的 PID，UID 关联用户身份。getpid()、getppid()、getuid() 各自返回一个数，由应用决定是否打印。Linux 下 ps 可查看进程快照，ps -l 增加 PID、PPID、状态等列，ps -a 扩大到有终端的其他进程，通常排除会话首进程。

自己试一次

播放器甲自己调用 getppid()，在表中关系仍然有效时返回哪个数？

核对推导

A · getppid 询问调用者的父进程。甲由 PID 为 510 的 shell 创建。

在 fork 的哪一边继续执行？

程序先把局部整数设为 4，再执行一次成功的 fork()。父子谁会回到 main 开头？

fork 创建子进程，父子都从调用的返回点继续。父得到子 PID，子得到 0；失败则只有原进程返回 −1。父子在逻辑上各有一份可独立修改的普通用户内存，同一打开文件的描述符则可能引用同一内核打开记录。复制了哪些状态，要逐种资源判断。

画进程树时，只对实际走到下一次 fork 的分支添孩子。若两边都继续，成功一轮后每个现有进程变成两条执行流；若只有旧父继续循环，得到扇形；若只有新子继续，得到链形。父子谁先被调度不由 fork 的返回值决定。

自己试一次

单个进程做四轮循环。每轮仅子进程继续循环，父立即跳出。假设全部 fork 成功，共曾有多少个进程（含起点）？

核对推导

A · 每一轮恰有一条分支抵达 fork，所以四轮新建四个，加最初进程为五个。

子进程退出之后还有什么留下？

后台转换任务结束后，系统还需把成功或失败告诉它的父进程。这个状态放在哪里？

从 main 返回（走到 main 结尾相当于返回 0）或调用 exit 会走 C 库正常终止路径，运行已登记的退出处理并刷新标准 I/O；_exit 直接进入低层终止。因未处理的终止信号或 abort 引发的 SIGABRT 退出，可能生成 core dump，正常退出处理程序不会依此执行。内核释放地址空间、关闭描述符并保存终止原因等供父进程领取。约定上，正常退出的状态码 0 表示成功，非零可由程序定义失败原因。

wait(&st) 等待任意可领取的子进程，waitpid(pid,&st,0) 可指定目标。成功返回子 PID；st 是编码状态，先用 WIFEXITED 或 WIFSIGNALED 区分，再取 WEXITSTATUS 或 WTERMSIG。子已经退出时可以立即领取；没有相符的子进程会报 ECHILD，受到信号中断有时需要处理 EINTR。

已经终止但尚待领取的子称为僵尸（zombie）。父先退出而子仍运行，子成为孤儿（orphan），在 Linux 中会被相应的收养进程接管，通常是 init 或已设置的 subreaper。

自己试一次

父收到 waitpid 返回值 610，且 WIFSIGNALED(st) 为真。610 表示什么？

核对推导

C · waitpid 的正返回值标识那名子进程。信号编号应通过 WTERMSIG(st) 从状态取出。

shell 怎样让子进程换成另一个程序？

用户输入打印一行文字的命令。若 shell 自己直接变成打印程序，提示符由谁再显示？

shell 解析命令后通常 fork 一名子进程。子用 exec 家族加载另一份可执行文件，将新程序的参数放入新地址空间，从其入口开始执行；PID 延续，原来的代码、堆和栈被替换。成功的 exec 不会回到旧函数；失败才返回 −1，子进程应报告并退出。父进程仍然执行 shell。

六个常见接口是 execl、execlp、execle、execv、execvp、execve。l 表示逐项列出参数，v 表示用向量；p 形式在程序名不含斜杠时按 PATH 搜索；e 形式显式给出环境。参数向量惯例上以程序名为 argv[0]，末尾有空指针。execve 是 Linux 的底层系统调用之一，其他常见形式由库包装。

前台命令通常让 shell 等子进程完成；以 & 提交的后台命令让 shell 先发下一次提示，仍须适时回收状态。典型开启作业控制的终端把 Ctrl-C 产生的 SIGINT 送给前台进程组。

char *args[] = {"printf", "%s\n", "ready", NULL};
execvp(args[0], args);
/* 到这里表示 exec 失败；此片段位于子进程。 */
_exit(127);
自己试一次

execvp 成功之后，下列哪件事发生？

核对推导

A · fork 负责产生新进程。exec 成功替换当前进程映像，因此旧调用点已经消失。

指针、数组和申请到的字节怎样区分？

要装六个 int，写 sizeof(p) 还是 sizeof(*p)？一个地址变量并不会自动带来六个可写位置。

进程可以用 malloc 从堆分配器申请一段连续可用的虚拟地址，参数以字节计，类型 size_t，失败返回 NULL。分配器向内核获取较大区域后自行分拆、复用，因而一次 malloc 未必对应一次系统调用。底层 brk 设置程序 break，sbrk 按增量调整它，mmap 可建立匿名或文件支持的映射。

指针 p 存着地址，*p 表示一个元素。固定长度本地数组 a 的 sizeof(a) 是整个数组的大小；数组作为普通函数参数时通常已调整为指针。若 int 为 4 字节、指针为 8 字节，六个 int 的数组占 24 字节，指向它的指针自身占 8 字节。sizeof 的结果以字节计，对固定类型通常在编译时已知。

/* 在包含 <stdlib.h> 的 main 函数中 */
int *p = malloc(6 * sizeof *p);
if (p == NULL) return 1;
p[0] = 12;
free(p);
自己试一次

在同一机器上，double 为 8 字节。double *p 指向七个元素，申请量应是多少？

核对推导

B · 七个 double 分别占 8 字节，需要 7×8＝56。指针自身的宽度无法表达元素数量。

如何检查一段动态内存是否还能读写？

要复制字符串“red”。三个可见字符后还需要一个位置；复制完还要决定最后由谁释放。

从三个问题检查每一次读写：指针是否指向仍然有效的对象？访问是否落在对象范围内？即将读取的值是否已初始化？只声明 char *dest 没有提供目标空间。strlen("red") 是 3，但 C 字符串以零字节结尾，保存完整内容需要 4 个字节。申请成功后 malloc 的内容尚未初始化，写入完成前不能读取其中的普通未初始化整数。

free 的对象应是分配器返回且尚未释放的首地址。一个对象可以有多个指针别名，任一别名释放对象后都失效。丢掉最后一个可管理的指针会造成泄漏，重复释放和释放后访问会带来未定义行为。free(NULL) 可以安全调用，把一个指针清空也不能修复其他悬空别名。

自己试一次

已有 p 指向成功分配的对象，q=p。执行 free(p) 并置 p=NULL 之后，q 的状态是？

核对推导

C · 释放影响的是堆对象的生命周期。赋值给 p 只改变 p 这个变量，q 仍保留一个失效的地址。

怎样给一张堆上的表扩容？

统计表从 3 项扩为 5 项。希望旧计数保留，分配失败时也还能使用旧表。

calloc(n,s) 申请 n 个大小为 s 的元素并将各字节清零，适合普通整数计数表。realloc(old,new_size) 可在原处调整，也可分配新位置并拷贝，在两种长度重叠的范围内保留内容。新增部分需自己初始化。

当新大小大于零，失败返回 NULL，旧块仍归调用方所有。先用临时指针接收返回值，确认成功才替换旧指针；成功之后按返回的新指针使用对象，也须重新取得任何指向内部元素的指针。若要释放所有容量，直接 free 可清楚表达意图。

自己试一次

用 p = realloc(p, n) 给非空 p 扩容，n>0，p 是唯一引用。若分配失败，问题是什么？

核对推导

A · 失败返回 NULL，直接覆盖唯一指针会使旧块变得无法访问，形成泄漏。

打开文件时，返回的小整数指向哪里？

把六个字节 ABCDEF 存入文件，同一进程两次 open 它。读第一份描述符会移动第二份的读取位置吗？

普通文件是可寻址的字节序列，目录把文件名关联到同一文件系统内的 inode 编号。路径标识名字，open 将一次打开变成进程的非负文件描述符（fd）。描述符是进程表的下标，指向内核的打开记录；其中保存当前偏移与打开状态，记录继续指向文件对象。分别 open 通常生成独立记录。在课件的 Unix System V 图中，这两层分别称作进程文件描述符表（FDT）和系统打开文件表（SFT），后者再引用内存中的 inode。

open 的访问模式如 O_RDONLY 或 O_WRONLY；O_CREAT 在缺少文件时创建，需另传权限 mode，实际权限还受 umask 影响；O_TRUNC 在合适的可写打开中将原文件长度清零。read/write 指明 fd、缓冲区和请求字节数，返回实际传输量，可能短读或短写；读取普通文件遇到末尾返回 0，错误返回 −1。close 释放本进程的一个描述符。

对普通文件，成功读写会让当前位置增加实际传输量。lseek(fd,d,whence) 可将它设为 d（SEEK_SET）、当前值加 d（SEEK_CUR）或文件大小加 d（SEEK_END），成功返回新位置。管道没有这种可寻址位置。

自己试一次

文件长 20，当前偏移为 6。执行 lseek(fd,-3,SEEK_END) 后完整读两字节。新偏移为多少？

核对推导

B · 以文件末尾为基准，先到 20−3＝17，随后读两字节到 19。

怎样让普通程序把输出写到文件？

命令写入标准输出 1。shell 如何在启动它之前，把这一次输出送往 report？

通常 0、1、2 分别是标准输入、标准输出和标准错误。重定向只需让描述符 1 指向目标文件的打开记录。dup(fd) 把同一记录复制到当前最小空闲描述符；dup2(fd,target) 直接把指定 target 安装为副本，适合明确重定向。别名共享同一打开记录以及其中的偏移。

假设原先 0、1、2 都关联终端，打开 report 得到 3。在子进程中关闭 1 后 dup(3) 会占据 1；另一种写法是直接 dup2(3,1)。关闭多余的 3 后，1 仍指向目标。exec 成功时一般会保留未设 close-on-exec 的描述符，新程序写 1 就到 report，写 2 仍到原终端。

自己试一次

若顺序是先关闭 0，再关闭 1，然后调用 dup(3)，它会占据哪个位置？

核对推导

A · dup 挑最小可用下标。0 和 1 都空闲，首先取 0，所以要精确指定输出时可以用 dup2。

为什么管道已经没数据，读者还在等？

用一条管道把生产者的标准输出接到计数程序的标准输入。生产者结束之后，读者是否一定收到 EOF？

先声明 int p[2]，再调用 pipe(p)。成功返回 0，同时把读端描述符放进 p[0]、写端放进 p[1]；失败返回 −1。内核维护有容量的单向字节流，没有消息边界；一次写的内容可能分几次读。先建立管道，再 fork，可以让不同进程继承指向同一管道两端的引用。生产者把写端安到 1，消费者把读端安到 0，随后各自关闭多余端点再 exec。

假设 shell 另行创建两名子进程，它自己也要关闭原有两端，再等待两者。正常阻塞模式下，空管道只要还有写端就会等；数据耗尽且所有写端关闭，read 返回 0。满管道上的写可能阻塞；所有读端关闭后再写会触发 SIGPIPE，若忽略该信号则 write 报 EPIPE。因此要先让两端都能运行，不能先等生产者结束才启动消费者。

再想一步

以 ls -l | wc -l 为例，ls 将目录列表写到 1，wc 从 0 读取并统计换行数。课件的独立演示程序只 fork 一次，让原进程执行 ls，子进程执行 wc；交互式 shell 自己还要发下一条提示时，通常保留 shell 并另建两个命令进程。两种安排都使用相同的读写端协议。

自己试一次

生产者已退出，消费者自己还保留了一份写端，管道现在为空。在通常的阻塞模式下 read 会怎样？

核对推导

B · 消费者自己的写描述符也计入写端引用，因此内核仍允许未来出现数据。

文件的原子替换和掉电持久各靠什么？

读者正在打开一份配置。更新程序不想让读者看到只写了一半的新版本，还希望掉电后名字可恢复。

直接截断原文件再写会有一段时间让其他打开者看到短文件。可以在目标的同一目录创建独立临时文件，完整写入新内容，检查每次实际写出的字节，并完成 fsync(tempfd)。fsync 成功意味着系统按接口要求完成该文件的数据及必要元数据同步。

再用 rename 把临时名替换为正式名。在同一文件系统的这个替换操作中，按正式名打开的读者会找到完整的旧对象或新对象；早先已打开的旧描述符继续引用旧对象。若还需让目录项的更新在掉电后持久，在支持此语义的系统中再 fsync 父目录。各步骤的错误都应处理。

自己试一次

临时文件已 fsync，rename 也已成功，但还没同步父目录。此时最准确的判断是？

核对推导

B · rename 已完成运行中的命名空间切换。新文件内容的同步和目录映射的同步是两次不同的承诺。

怎样列目录、读属性和删除目录？

对一个目录运行 ls，程序如何先找到名字，再询问其中一个文件的所有者和长度？

目录也是文件系统对象，它保存名字到 inode 的映射。. 表示当前目录本身，.. 表示父目录，在普通根目录两者都回到根。mkdir(path,mode) 建目录；rmdir(path) 要求目标除特殊项外为空。普通文件的名字用 unlink 移除。绝对路径从根开始，相对路径从进程的当前目录开始。

opendir 返回用于遍历的 DIR 目录流，readdir 每次返回一条含 d_name、d_ino 等字段的目录记录，结束时返回 NULL，closedir 释放资源。遇错也可能返回 NULL，严谨代码可在读取前清 errno 并在返回 NULL 后检查。类型提示 d_type 可能不可用。

stat(path,&s) 通过路径查属性，fstat(fd,&s) 通过已有描述符查。st_mode 含类型和权限，st_uid 和 st_gid 为属主属组，st_dev 与 st_ino 合起来识别文件，st_size 为逻辑字节数，st_nlink 为硬链接数，在 Linux 上，st_blocks 按 512 字节单位记录已分配空间，st_blksize 给出建议 I/O 大小。特殊设备文件还可用 st_rdev 标识它代表的设备。atime 记录访问，mtime 记录内容修改，ctime 记录状态变更。

自己试一次

若先打开了文件又删掉它最后一个名字，要从仍有效的 fd 查询文件长度，该用什么？

核对推导

B · fstat 从已有的打开文件描述符找到对象，无需重新解析已经删除的名字。

硬链接和符号链接在改名后各会怎样？

draft 和 saved 是同一个文件的两个硬链接，另有一个符号链接 current 保存字符串 draft。删除名字 draft 后还能打开谁？

同一文件系统内的硬链接是指向同一 inode 的另一个目录项。link(old,new) 建立新名字并增加硬链接数，写任一名字都改变同一对象。unlink 只删除一个名字并使计数减一；计数为零且不再有打开引用后，空间才可最终回收。通常不允许用户给目录建立硬链接，以免破坏目录树。不同文件系统的 inode 编号各自解释，硬链接无法跨越该边界。

符号链接有自己的 inode，内容是目标路径字符串，长度通常是该字符串的字节数。路径解析到它时会继续寻找目标；相对目标从链接所在目录解释。它可指向目录或跨文件系统，也能在目标消失时作为悬空链接继续存在。stat 通常跟随符号链接，lstat 可查看链接本身。若只把 draft 改名为 final，saved 作为硬链接仍指向同一 inode；符号链接 current 内保存的字节仍拼作 draft，在原位置找不到它就会悬空。

自己试一次

把 current 指向的相对目标设置为 ASCII 字符串 old/report，链接本身通常记录多少字节？

核对推导

C · old 有 3 个字节，斜杠 1 个，report 6 个。符号链接保存这 10 个路径字节。

子进程换了目录，父进程从哪里继续？

假设 shell 在 /a 目录中。它让一个新子进程调用 chdir("/b") 并退出。父进程随后执行 pwd，会显示哪个目录？

展开推导
  1. fork 后子进程继承父进程当时的工作目录，但各自持有自己的工作目录状态。
  2. 子进程的 chdir 只更新子进程的状态。等它退出并回收，父进程仍在 /a。
  3. 因此希望影响后续命令的 cd 需要在 shell 自身的执行上下文中生效。管道里的普通外部命令则可用子进程执行。

参考本期 HW01 教程与管道图解，以及历史 T02、T03 的 shell 例。此处路径自编。
