# 数字消消乐：关键实现要求与纯 C AI 方案

这是一份针对 ESTR1002 Number Crush 项目的设计建议，不是已实现、已跑分的程序。题目硬要求以 [完整中文说明](ESTR1002-消消乐-中文说明.md) 及用户提供的原 PDF 为准。以下的模块划分、算法、参数和测试案例均为补充建议；题目没有指定必须使用机器学习。

## 一、先抓住八个硬要求

| 要求 | 实现含义 | 原文 |
| --- | --- | --- |
| 两个 C 交付物 | 基础程序支持人类交互；AI 单独提供指定函数 | pp.2、8、10–11 |
| 棋盘与操作编码 | int board[100]；索引 0–99；操作编码为 a×100+b | pp.5–6 |
| 相邻即可算有效 | 不能要求交换后必须消除；非法操作重新输入，不消耗有效步数 | pp.2、6、10 |
| 同轮先找齐、后消除 | 扫描全部最大水平/竖直段，计分后取消除格子的并集，再统一清空 | pp.3、8 |
| 两种奖励都实现 | 五连及以上清整行/列但只按段长计分；第 r 轮乘 r | pp.3–4 |
| 随机序列严格一致 | 使用助教 TinyMT；先全部下落，再逐行从左到右补数；初始消除不计分 | pp.6、9 |
| 100 次有效交换结束 | 每步连锁处理到稳定；最后显示总分和最终棋盘 | pp.4、10 |
| AI 接口、性能及文件限制 | 不改 board、不打印、无 main；实验室每次调用 ≤5 秒；所有函数加学号后缀；只交指定 .c/.h | pp.8、10–11 |

优先级：先把基础引擎做对，因为它占课程 9%，且所有搜索策略都依赖正确模拟。AI 基本部分占 3%，排名奖励最高再加 3 分。

## 二、C 程序应该怎样拆

### 1. 棋盘、合法动作和返回值

固定数组足够，不需要复杂容器。遍历每个格子，只生成“向右”与“向下”的交换：水平 10×9=90 个，竖直 9×10=90 个，共 180 个无重复动作。这是由棋盘尺寸推导出的数量，不是额外题目规定。

合法性判断应按行列坐标，不能只判断 abs(a-b)==1，否则会错把 09 与 10 当成水平相邻。

```c
/* 示意：studentID 在正式代码中替换成真实学号 */
int valid_studentID(int a, int b)
{
    if (a < 0 || a >= 100 || b < 0 || b >= 100) return 0;
    int dr = a / 10 - b / 10;
    int dc = a % 10 - b % 10;
    if (dr < 0) dr = -dr;
    if (dc < 0) dc = -dc;
    return dr + dc == 1;
}
```

输入解码用 a=move/100、b=move%100；输出编码用 100*a+b。位置 00 的前导零不保存在 int 中，例如 00↔01 的编码数值为 1，显示时可用 `%04d` 得到 0001。AI 不应自行打印。这里的“四位”是位置编码格式，不应仅凭 int 的显示位数排除涉及 00–09 的合法交换。

相同数字互换也符合题面的相邻规则，只是棋盘不变。策略可以降低它的优先级，不能把它写成引擎非法规则。

### 2. 检测、计分和清除必须分开

建议接口职责：

```c
/* 返回所有匹配段的基础分之和，并填好消除掩码 */
int mark_runs_studentID(const int *board, unsigned char *mask);
/* 按 mask 清空，再保持每列原有相对顺序向下压实 */
void clear_and_fall_studentID(int *board, const unsigned char *mask);
```

扫描每一行与每一列，用“起点 start + 终点 end”找到最大的连续相同段，长度 L=end-start。L≥3 时加 L*(L-1)/2；将匹配格标入 mask。L≥5 时把整行或整列标入 mask。所有扫描结束才清除，避免先消横段导致竖段漏检。

计分按匹配段累加，清除按布尔掩码取并集。因此十字交叉可以得两段分，交点却只清一次。五连清除的附带格子不会凭空产生新的匹配段分数，也不会因为里面有某种数字而额外触发整行/列奖励；题目没有这种“特殊糖果”规则。

### 3. 连锁处理的边界

交换之后令 r=1、step_score=0。找不到匹配就结束；有匹配则累加 r×base_score，清空、下落、补数，令 r 加 1，再检查。每个新交换重新从 r=1 开始，不能把上一步倍率带到下一步。

初始化也调用同一套稳定化流程，但丢弃得分，不占 100 步。无效输入不改变棋盘、分数、步数或随机状态。合法而不消除的交换计一步，得 0 分，也不需要消耗补数随机数。

真实游戏引擎必须处理到稳定，不能为了速度强制截断连锁。AI 内部模拟可以设置安全预算，但超时或截断的轨迹应标为未完成，不能伪装成精确完整得分。

### 4. 两套随机状态，避免 AI 改变真实游戏

基础游戏必须使用助教版本 TinyMT 和题目指定调用顺序。不要用 rand() 或自行下载的不同参数版本替代官方生成器。TinyMT 的官方说明可用于理解库背景，但不能替代本项目助教文件。

AI 搜索在自己的棋盘副本和独立伪随机状态中运行。它只收到 K、board，不收到游戏种子或 TinyMT 状态，因此不应假定知道真实的下一个补入数字。局部模拟是对未知补数的抽样估计。

AI 的随机函数可自包含在提交的 .c 中并加学号后缀，避免依赖额外提交文件或操作评分器的全局随机状态。需要高质量抽样；不要为每个候选动作反复调用 srand(time(NULL))。初始化一次局部状态，用不同 rollout 的随机流做重复试验。随机流固定有利于调试复现，但不等于知道官方未来随机数。

## 三、五种可用纯 C 实现的方案

下表中的开发难度是设计判断，不代表实测耗时或排名。

| 方案 | 做法 | 能看到什么 | 主要代价与局限 | 建议用途 |
| --- | --- | --- | --- | --- |
| A 一步穷举贪心 | 试全部 180 个动作，取第一轮真实分最高者 | 当前立即收益 | 看不到随机补数和未来布局 | 必做基线 |
| B 两步前瞻与束搜索 | 保留少量候选，向后再看一至数步 | 零分铺垫与短期组合 | 遇补数必须采样，分支很快增多 | 补强 K 较大时的铺垫 |
| C 蒙特卡洛模拟 | 每个候选多次随机补数和短期试玩，比较平均回报 | 连锁概率、未来几步收益 | 有抽样噪声，依赖模拟器速度 | 推荐主方案 |
| D 随机环境 MCTS/UCT | 动态把模拟次数分给值得探索的动作和后继 | 更深的自适应搜索 | 随机后继多，内存和实现更复杂 | 有时间再冲性能 |
| E 线性价值函数或小型网络 | 用 C 训练/调参，将参数固化成 C 数组快速评分 | 从大量对局学到局面价值 | 需要训练、验证，可能过拟合 | 后期增强，不是起步必需 |

### 方案 A：一步穷举贪心

对每个相邻交换，复制棋盘、执行交换，检测当前所有匹配段，计算第一轮基础分。选分数最高的动作即可。每个动作扫描约 100 个格子量级，180 个动作的工作量很小，但实际时间仍取决于实现与机器。

例子：动作甲制造一个四连，立即 6 分；动作乙制造互相交叉的两个三连，也是 6 分；动作丙制造一个五连，立即 10 分且会清整行。这个方法会优先选丙。

同分时可优先清除更多格子的动作，或使用布局特征；这些仅是启发式，不是保证更优的定理。五连清掉 10 格不等于直接获得 B(10)=45 分。

当所有动作立即都为 0 分时，纯贪心容易不断做无意义交换，因此必须有合法回退，并最好调用方案 B。随机选合法动作只能作为调试基线，不保证一局获得非零分。

### 方案 B：两步前瞻与束搜索

先挑出一批值得看的第一步，再考虑第二步。如果第一步不消除，交换后的棋盘完全确定，可以准确枚举下一步的第一轮得分。这正适合“第一步搬数字、第二步形成三连”的局面。

对全部零分第一步做二步检测最多涉及 180×180=32,400 个动作对；每个动作对仍需匹配扫描。是否可直接穷举应在目标机器测量。

若第一步有消除，后继棋盘包含未知随机补数。这时不能假装有唯一后继；需要对每个第一步采样若干次完整连锁稳定化，再在每个样本上选择下一步。

一种两步价值写法：第一步完整得分 + gamma×第二步预计得分。gamma=1 对应不折扣的短期得分；小于 1 是人为偏重眼前收益的近似，题目没有规定折扣。

束搜索（beam search）只保留宽度 W 的候选路径，再向后扩展。W=8、16、32 可作为调参起点，不是已验证的最优值。不要只保留立即得分最高的动作，否则可能把需要铺垫的零分动作全丢掉。

### 方案 C：蒙特卡洛模拟加短期 rollout（推荐）

对每个候选动作多次“假想游戏”，用独立随机数补数。每次先把当前交换引起的所有连锁结算完，再用一个便宜策略继续玩几步；最后比较平均得分。

计算方式：Q(a) = M 次模拟回报之和 / M。模拟回报可以只取当前交换总分，也可以加随后 H 步的分数。这里 M 是每动作样本数，H 是额外向前试玩的步数。

建议实现分两层：

1. 先对全部 180 个动作做少量完整单步模拟，保留高平均分候选，并为铺垫动作保留名额。
2. 对候选追加更多模拟，使用一步贪心或廉价布局策略做后续 H 步；每一模拟步都处理完整连锁。

例如先试 M=8，再对 12–20 个候选做额外模拟，H=2–4，均只是起始调参配置。不要在未测量前承诺这些参数能满足 5 秒；K=4 的连锁较长，可能反而更耗时。

可以让不同候选在第 j 次试验使用同一份初始模拟随机状态，减少部分比较噪声；不同候选消耗的随机数个数不同，因此随机轨迹会分叉，不能认为它们最终经历了完全相同的棋盘。

缺点是小样本可能偏爱偶然的高分连锁。应追加样本检验领先候选，比较均值而不是取一次模拟的最高分。老师“每个 K 四局取最好两局”的规则作用于完整对局，不代表每一步应该选择单次最高模拟值。

### 方案 D：随机环境 MCTS / UCT

蒙特卡洛树搜索通常反复执行选择、扩展、模拟和回传。UCT 用当前平均回报和探索项一起决定接下来采样哪个动作，让表现好或样本不足的动作得到更多计算。

常见选择式可写为：平均回报 + c×sqrt(log(父节点访问次数)/动作访问次数)。零访问动作需单独优先处理。分数尺度变化大，探索参数 c 需要和回报尺度匹配，不能照抄其他游戏数值。

本项目的关键是随机后继：同一个交换在不同补数下会出现不同棋盘。可以用状态节点、动作节点与抽样后继表示随机性，或采用只按动作历史建树的 open-loop 近似。后者能减少存储，但会混合不同实际棋盘的统计，应认识到这是近似。

C 可用固定容量节点池与整数索引管理节点，避免频繁 malloc/free。每次调用达到时间预算或节点上限就返回当前最好合法动作。UCT 会用到 log/sqrt，是否需要额外数学库链接选项要在助教编译方式中确认。

UCT 原论文介绍了用 bandit 思想引导蒙特卡洛规划；它并不证明本题中 MCTS 必然胜过简单 rollout。这里的随机后继结构和节点池设计是针对项目的建议。参考：[Kocsis 与 Szepesvári，2006](https://aima.cs.berkeley.edu/~russell/classes/cs294/s11/readings/Kocsis%2BSzepesvari%3A2006.pdf)。

### 方案 E：学习型价值函数，仍然全部用 C

最轻量做法是线性函数 V(board)=w1×f1+…+wn×fn。特征可包括：下一步能立即得分的动作数、最好立即得分、潜在五连机会、相同数字的局部分布。特征权重并不是题目给定的。

用 C 写自对弈模拟和随机搜索/爬山调参，比较完整 100 步对局成绩；将最终权重作为 const 数组写进 .c。也可以在 C 中实现小型神经网络与训练，但开发和验证成本更高。不能在用户要求“必须 C 实现”时把核心训练偷偷交给 Python 框架。

学习函数可以给方案 B/C 的搜索叶子估值，减少 rollout 长度。训练种子、调参种子、最终测试种子分开，分别统计 K=4、5、6、7，避免只记住几个样例。

如果选择神经网络，提交时应自包含参数和推理代码，不依赖运行时外部模型文件或网络服务。模型输入只用接口允许的信息。

## 四、我建议的具体组合

推荐 A → C，再用 B 处理无立即得分的局面；有充分时间和测试证据再尝试 D/E。

实际决策流程：

1. 先枚举 180 个动作，计算立即得分、清除数等便宜特征，并立刻保存一个合法回退动作。
2. 若所有动作立即得分为零，用两步检测找能创造下一步机会的搬运动作。
3. 对全部动作进行少量完整连锁抽样，不让第一轮贪心彻底封死候选。
4. 对高潜力候选增加短期 rollout，持续记录平均回报及样本数。
5. 临近预算时停止采样，返回目前证据最好的合法动作；任何搜索失败都回退到已保存合法动作。

这个组合能先获得一个简单可测的基线，再逐步引入随机连锁与短期布局。是否强于纯贪心，要靠完整对局对照实验判断。

可将内部预算先设为约 3.5–4 秒，以留出返回和机器波动余量，但必须在 ERB 909 或可比机器校准。标准 C 的 clock() 测的是 CPU 时间，并不等于严格墙钟时间；正式计时方式应匹配评分环境。检查时间不能只放在最外层，长连锁和内层搜索也需要检查。中断一条轨迹时舍弃未完成结果，保留此前完整样本。

接口没有传剩余步数，因此不要未经确认就依赖 static 计数推断“当前是第几步”：同一进程可能连续运行多局，且没有明确重置通知。先设计无状态决策，避免后续对局继承错误进度。

## 五、最值得先做的自编测试

下列案例是补充测试设计，不是官方样例。测试局面应隔离无关匹配，避免额外分数干扰。

| 测试 | 应验证的结果 |
| --- | --- |
| 仅一个三连 | 基础分 3；消除 3 格 |
| 仅一个四连 | 基础分 6，不能按两个重叠三连重复计分 |
| 两个三连交叉 | 基础分 6；消除 5 个不同格子 |
| 仅一个水平五连 | 基础分 10；整行 10 格消除 |
| 同轮有多处横竖匹配 | 先统一计分/标记，再一次性清除 |
| 第一轮三连+四连，第二轮五连 | 一步共 29 分；下一步倍率回到 1 |
| 初始随机棋盘含匹配 | 清到稳定，初始总分仍为 0、步数仍为 0 |
| 09 与 10 | 非法相邻，不应接受 |
| 合法相邻但没有消除 | 消耗一个有效步，得分 0，不补数 |
| 一列多处空格 | 下落后非空数字保持原来上下相对顺序 |
| 多列同时出现空位 | 所有列压实完，再按全局行优先顺序补数 |
| AI 调用前后比较原数组 | 100 个元素全部不变 |
| 连续调用 AI、重复多局 | 始终合法、不崩溃、无任何输出 |
| 第 100 次有效交换产生连锁 | 结算全部连锁后才结束游戏 |

基础引擎最终必须对照 Blackboard 两个官方样例，逐步比棋盘和分数；本次只收到说明 PDF，尚未取得这些样例和 TinyMT 附件。

算法比较则对 K=4、5、6、7 分别运行多组未参与调参的种子，记录完整 100 步得分、每步耗时、最坏耗时、非法动作数与崩溃数。同时按老师“四局取最高两局”的方式分组统计，避免只看单步分数或某一颗种子。共享初始种子便于对照，但不同策略消除数不同，会消耗不同长度的随机流，不能称为完全相同后续局面。

## 六、提交前对照与当前结论

基础提交 basic_<studentID>.zip 只含 .c/.h，并带助教规定的 TinyMT 文件。AI 只交 aiplayer_<studentID>.c 与 .h，入口为 ai_player_<studentID>；所有辅助函数同样带学号后缀。AI 不含 main、不打印、不写入 board，不靠额外文件才能运行。

目前完成的是中文版、要求提炼与五类算法设计，尚未编写完整游戏、AI 或进行性能跑分。最适合先落地的是“一步穷举 + 独立随机模拟 + 短期 rollout”，不是直接训练大型模型，也无需调用在线 AI API。
