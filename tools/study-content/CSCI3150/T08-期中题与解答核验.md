### p.7–9：A正确，B和C各错在一个概念

> **p.7** A:
>
> correct. When a user process makes a system call, it requests services from the operating system’s kernel. To execute these privileged operations, the CPU must switch from user mode to kernel mode. This is a fundamental mechanism of operating systems.

> **p.8** B:
>
> exec() replaces the entire address space of the current process with a new program, including the stack, heap, and data segments. None of the original variables are accessible anymore.

> **p.9** C:
>
> After fork() , the child process continues execution from the point where fork() returns, not from the beginning of main() .

A描述真实系统调用进入内核的基本机制。B在题目成功exec前提下错误，新程序替换原映像，原栈对象不继续存在；若exec失败返回则不能套这结论。C错误，fork父子从返回点继续，只是返回值不同，子0、父正PID。

### p.10–11：重定向保留stdout角色，线程有独立栈指针

> **p.10** D:
>
> After redirection, the process can still "print" to standard output—the output just goes to the file instead of the terminal.

> **p.11** Explanation
>
> A:  The heap is a region of a process’s memory used for dynamic memory allocation. It is accessible by all threads of the same process, facilitating data sharing and communication within the process.
>
> B: File descriptors are handles used by a process to access files or I/O resources. In a multi-threaded process, all threads share the same set of file descriptors.
>
> C: The stack is used to store a thread’s execution history, including function calls, return addresses, and local variables. The stack pointer points to the top of the current thread’s stack.
>
> D: Global variables are stored in the process’s data segment.
>
> (You can also refer to page 7-8 in lec4-threads)

D错误：stdout仍是fd1，重定向只是让它指向文件，所以还能打印，文字目的地改变。

Q1(b)完整选项（试卷p.1）：同进程两线程不共享哪项？A Heap；B File descriptors；C Stack pointer；D Global variables。答案C。堆、fd表、全局对象属于共享进程资源；栈指针属于线程执行状态，切换时分别保存。不要把“栈指针不共享”误推成“通过指针绝无可能访问别的线程栈对象”。

### p.12–13：第二题先写fork返回规则

> **p.12** A quick review of fork():
>
> The fork() creates a new child  process, by duplicating the parent process.
>
> Child Process Start Point: After a successful fork(), both the parent and child processes continue execution independently from the point immediately following the fork() call.

> **p.13** The fork() function returns different values to the parent and child processes
>
> In the Parent Process: Returns the Process ID (PID) of the newly created child process (a positive integer).
>
> In the Child Process: Returns 0.
>
> On Failure: Returns -1 in the parent process.

图p.12父子都从fork之后继续；p.13分成功父返回正PID、子返回0、失败返回-1。本题答案隐含fork全部成功，并按每次printf调用计数；如果改变输出缓冲环境，还需另行讨论fork复制未刷新的stdio缓冲，不能从题目模型泛化所有运行方式。

试卷p.1–2原题核心程序如下，保留其 `void main` 教学写法；实际标准C入口应为int main。问题(a)包含Shell新建的初始程序进程共有多少；(b)#和!各输出多少。

```c
#include <stdio.h>
#include <unistd.h>
void main() {
    int i;
    int pid;
    for (i=0; i<4; i++) {
        if (i % 2 == 0) {
            pid = fork();
            if (pid == 0) printf("#\n");
        } else {
            printf("!\n");
        }
    }
    return;
}
```

| i | 开始进程数 | 动作 | 结束进程数 | 本轮输出 |
|---|---|---|---|---|
|0|1|唯一进程fork|2|新子打印#一次|
|1|2|都不fork|2|!两次|
|2|2|两进程各fork|4|新子各打印#，两次|
|3|4|都不fork|4|!四次|

故共4个程序进程，其中3个新子；#为1+2=3，!为2+4=6。课件列举的九行不是唯一调度输出顺序，因不同进程可交错；计数相同不表示全局顺序固定。

### p.19：Q3原答案与跨等待的缺陷

**课件程序与接口（p.19，原页片段）**

```text
#include <stdio.h>
#include <pthread.h>
#include <unistd.h>

#define MAX_MEAT 5
#define MAX_BREAD 10

pthread_mutex_t mutex = PTHREAD_MUTEX_INITIALIZER;
pthread_cond_t cond_meat = PTHREAD_COND_INITIALIZER;
pthread_cond_t cond_bread = PTHREAD_COND_INITIALIZER;

int meat = 0;
int bread = 0;
int shawarma = 0;

void* meat_supplier(void* arg) {
    while (1) {
        pthread_mutex_lock(&mutex);
        if (meat == 0) {
            meat = MAX_MEAT;
            printf("Meat supplier refilled the meat.\n");
            pthread_cond_signal(&cond_meat);
        }
        pthread_mutex_unlock(&mutex);
    }
    return NULL;
}
```

**课件程序与接口（p.19，原页片段）**

```text
void* bread_supplier(void* arg) {
    while (1) {
        pthread_mutex_lock(&mutex);
        if (bread < MAX_BREAD) {
            bread++;
            printf("Bread supplier added a bread. Total bread: %d\n", bread);
            pthread_cond_signal(&cond_bread); // Notify producers
        }
        pthread_mutex_unlock(&mutex);
    }
    return NULL;
}

void* producer(void* arg) {
    while (1) {
        pthread_mutex_lock(&mutex);
        while (meat < 1) {
            pthread_cond_wait(&cond_meat, &mutex); // Wait for meat
        }
        while (bread < 2) {
            pthread_cond_wait(&cond_bread, &mutex); // Wait for bread
        }
        // Produce one shawarma
        meat--;
        bread -= 2;
        printf("Producer made a shawarma.\n");
        shawarma++;
        pthread_mutex_unlock(&mutex);
    }
    return NULL;
}
```

**课件程序与接口（p.19，原页片段）**

```text
refill if empty;
else do nothing
```

**课件程序与接口（p.19，原页片段）**

```text

else do nothing
```

参考答案字母依次 **A、E、D、F、G、H**，对应可见代码：

| TODO | 原答案含义 |
|---|---|
|1|`meat == 0`|
|2|`pthread_cond_signal(&cond_meat)`|
|3|`bread < MAX_BREAD`|
|4|`pthread_cond_signal(&cond_bread)`|
|5|`pthread_cond_wait(&cond_meat,&mutex)`|
|6|`pthread_cond_wait(&cond_bread,&mutex)`|

这与原评分键一致，但两个独立while不足以保证两个制作人在所有交错下安全。**代码审查反例（补充）**：可达状态meat=1、bread=0。P1通过肉检查，因缺面包释放mutex等待；供应者逐次补面包，P2抢先拿到2片并消费最后1肉，使meat=0；在肉供应者尚未补货前再供应2片面包，P1被唤醒、重新得锁，跳出面包循环后不再检查肉，执行meat--得到-1。

修复原则是在真正扣减前重新验证组合谓词 `meat>=1 && bread>=2`，任一等待释放锁后回到组合检查，并设计与资源变化匹配的通知机制。这里的反例是对程序正确性的分析，不冒充官方更正，也不据此擅自改原题评分字母。

**补充：把Q3反例拆成可逐行检查的状态。** 两个while各自正确，不代表两者的结论能跨越一次wait一起保留。下面从原程序可达的肉1、面包0状态开始；表中操作均在同一mutex保护下，wait会释放它。

| 步 | 动作 | meat | bread | P1掌握的信息 |
|---|---|---:|---:|---|
| 1 | P1通过肉检查，因缺面包wait | 1 | 0 | 只知道过去某时刻肉够 |
| 2 | 供应者补两片面包 | 1 | 2 | P1尚未重得锁 |
| 3 | P2抢先制作一份 | 0 | 0 | 旧肉结论已失效 |
| 4 | 面包供应者再补两片，肉供应者尚未运行 | 0 | 2 | P1可因面包通知醒来 |
| 5 | P1只重查bread，随后扣肉 | −1 | 0 | 发生资源不变量违反 |

不是mutex失效，而是P1主动wait期间允许别人合法改变meat。正确判据应在最终扣减前同时成立；每当释放过锁，此前依赖共享状态的判断都要重新确认。参考填空字母仍按来源保留，反例指出的是完整程序的额外缺陷，不能把两种证据混在一起。

### p.23–24：Q4答案与容量边界

**课件程序与接口（p.23，原页片段）**

```text
#define NUM_SEATS 6      // Number of available seats
#define NUM_WAITERS 4    // Number of available waiters
#define NUM_CUSTOMERS 12 // Number of customers

sem_t seats;    // Semaphore for available seats
sem_t waiters;  // Semaphore for available waiters

void* customer(void* type) {
    sem_wait(&seats);
    sem_wait(&waiters);
    order(); // The customer is ordering.
    sem_post(&waiters);
    eat(); // The customer finishes eating.
    sem_post(&seats);
    pthread_exit(NULL);
}

int main() {
    pthread_t customers[NUM_CUSTOMERS];
    sem_init(&seats, 0, NUM_SEATS);
    sem_init(&waiters, 0, NUM_WAITERS);
    for (int i = 0; i < NUM_CUSTOMERS; i++) {
        pthread_create(&customers[i], NULL, customer, &customer_types[i]);
    }
    /* ... */
}
```

> **p.23** Requirements: customers must have a seat and then receive service from a waiter before they can begin ordering. When the order is taken, the waiter leaves. When the meal is finished, the customer leaves the seat.
>
> Try to get a seat via wait()
>
> Try to get a waiter via wait()
>
> Order()
>
> Release the waiter via post()
>
> Eat()
>
> Release the seat via post()

四行依次为 `sem_wait(&seats);`、`sem_wait(&waiters);`、`sem_post(&waiters);`、`sem_post(&seats);`。同一时刻占座不超过6，接受点单服务不超过4，吃饭者也占座但不占服务员。前六人可占满座位，其中最多四人点单、其余等服务员，余下六人等座位；已有顾客点完会释放服务员，故这个获取顺序自身未形成资源环。

图中的编译错误提醒不能对sem_t直接做 `seats--`，必须走同步API。p.24为Q&A。本篇A类证据仅证明这些题型出现在历史Spring2026期中，不证明当期试卷安排。

:::hint 自测：Q4若顾客吃完才释放服务员，座位/服务员计数仍不超限，为什么仍不符合原题？

安全容量没超，不表示协议语义正确。原题规定服务员点单结束就离开；吃饭期间继续占用服务员，会无谓降低其他顾客点单机会，也改变了资源寿命。检查程序至少有三层：是否违反容量、是否可能卡死、是否在题目规定的时刻获取和释放。只检查信号量初值不能覆盖后两层。

:::endhint
