## 文件名字、打开状态与字节偏移

### 从持久化需求到文件和目录（p.2–4）【延伸 L01 p.46–48】

p.2 的课程图将本讲定位在系统调用，p.3 的接口图把请求交给内核文件系统与设备层。p.4 提出即使掉电也要保持数据的需求，并引出两个抽象：文件与目录。它们把程序从“知道磁盘哪个物理位置”提升到“通过名字读取一组字节”。

> **p.4** Two key abstractions in the virtualization of storage

文件负责承载内容，目录负责命名和组织；持久化是目标，文件与目录是实现这个目标时程序使用的接口抽象。

### 目录保存名字到inode的映射（p.5）【新】

> **p.5** It contains a list of (file name, inode number) pairs.

**inode number** 是文件系统内部的对象编号，文件名则是人使用的名字。目录项把名字连接到inode，因此目录树是查找对象的一种路径组织。

表（p.5）：dirA示例中的目录项

| inode number | file name |
|---:|---|
| 123 | . |
| 247 | .. |
| 220 | dirB |
| 230 | My1.dat |
| 230 | My2.dat |

图（p.5）：目录树与目录项
元素：根 / 下有 dirC、dirA；dirA 下有 dirB、My1.dat、My2.dat；dirB 内另有 My1.dat。表中两个名字映射到230。
看什么：相同短文件名可以出现在不同目录；不同名字也可以指向同一inode。名字与对象不是一一对应。

### open返回的是描述符，不是inode（p.6–7）【新】

> **p.7** A file descriptor specifies the index into file descriptor table (FDT) of the process.

p.6 用O_CREAT创建不存在的文件，O_WRONLY选择写方式，O_TRUNC把已有内容截为0字节。**补充**：实际以O_CREAT创建时须提供权限参数；本页省略参数的示意式不能直接当完整调用。read/write返回实际传输字节数，不保证每次等于请求长度。

p.7 图中 fd 是本进程FDT的下标，FDT项指向系统打开文件表SFT，SFT再指向inode。偏移和打开方式属于打开状态；两个独立open可以指向同一inode，却保持不同偏移。图中0、1、2已占用，新open得到3；这是本例条件，不是open永远返回3。

图（p.7）：FDT→SFT→inode
元素：FDT第3项指向一个SFT项，多个SFT项可指向同一inode；0/1/2标为标准输入、输出、错误。
看什么：必须区分描述符编号、打开文件状态与文件对象三层。

### 偏移怎样自动或手工变化（p.8–9）【新】

> **p.8** An open file has a current offset.

p.8 的current offset决定下一次读写起点。一次实际传输N字节后偏移增加N，不是增加请求参数中未必完成的数量。p.9 的SEEK_SET从文件开头算，SEEK_CUR从当前偏移算，SEEK_END从当前文件长度算；lseek只改定位状态，不执行读写。

**算一遍（补充；数字是我为演示取的，讲义没给）**：文件长100字节，当前偏移20。lseek(fd,5,SEEK_SET)得到5；接着实际读8字节后为13；lseek(fd,−3,SEEK_CUR)后为10；lseek(fd,−10,SEEK_END)后为90。最后一步的基准是100，而不是上一步10。

## 重定向改变的是描述符关系

### dup选择哪个编号（p.10–12）【新】

> **p.11** On success, return the new file descriptor.

p.10 的重定向让标准输出编号1指向另一个打开对象，因此命令无需知道它在写终端还是文件。p.11 的dup复制fd引用，选择最小未用编号；不是把整个文件复制一份。

p.12 的流程是open文件、close(1)、dup(fd)、close(fd)、execvp。按0/1/2原来都打开、open取得3计算：关闭1后，最小空槽为1；dup(3)把1连到同一打开对象；关闭3仍保留1；exec后ls写1就写文件。**补充**：一般代码可用dup2指定目标，并须检查错误；这个例子成立依赖1确实是最小空槽。

## 用管道把一个命令的输出变成另一个的输入

### 管道两端与讲义问题（p.20）【新】

pipe(fd)在数组中写入两个描述符：fd[0]读、fd[1]写；调用本身成功返回0。数组中端点值与系统调用返回值不能混淆。

### 阻塞、EOF与SIGPIPE的条件（p.29）

> **p.29** The communication channel provided by a pipe is a byte stream: there is no concept of message boundaries.

空管道有写端仍打开时，阻塞式read等待数据；所有写端引用关闭且缓冲数据读完后，read才返回0表示EOF。因此“某个写进程结束了”不足以证明EOF，如果另一个进程还持有写端，读者仍可能等待。

另一方向上，所有读端关闭后继续写，会产生SIGPIPE；忽略信号时write失败并给出EPIPE。它不是“写者收到EOF”，EOF是读操作的返回语义。**算一遍（补充；数字是我为演示取的，讲义没给）**：两次write分别写3和2字节，读取者一次最多请求5字节，可能一口读到5，也可能分几次；管道没有保留“第一个消息/第二个消息”的边界。

## 文件内容的提交与名字的修改

### write返回与fsync完成（p.30–31）【新】

> **p.30** The file system will buffer writes in memory for some time (for performance reasons), e.g. 5 or 30 seconds.

p.30 用写缓冲解释为何write很快返回却不等于掉电后内容安全。缓存中的脏数据还没写到存储设备。fsync请求完成相应同步写入，成功返回0；p.31 示例同时检查write实际长度与fsync结果。

p.31 还指出有时需要同步包含foo的目录，因为文件内容和“目录中出现这个名字”是两份不同状态。**补充**：不能把例子里的5或30秒当作所有系统固定刷盘周期，也不能在未检查失败时宣称持久化已经完成。

### 临时文件与原子改名（p.32）

> **p.32** How to update a file atomically:

课件先写foo.txt.tmp，fsync并close，再rename为foo.txt。目的在于让名字切换发生在新版本准备好以后，而不是在旧文件上逐块覆盖时让读者看见半新半旧。**算一遍**：示例 `char buffer[20]="hello"` 的数组总长20；write使用sizeof(buffer)，因而写20字节，其中hello是5字节，剩下15字节为零初始化部分，而不是只写5个字符。

**补充**：原子名字替换与断电持久化是不同保证；完整崩溃安全流程还需考虑目录同步、错误处理和文件系统条件。本页的rename教学模型不授权把跨文件系统移动称为一次原子rename。

### stat字段与文件实际占用（p.33–34）

> **p.33** Metadata is information about each file.

p.33 的stat结构描述对象而非返回文件内容：st_ino是inode号、st_mode含类型与权限、st_nlink是硬链接数、st_size是逻辑字节长度、st_blocks是已分配块计数。三个时间字段分别涉及访问、修改内容和状态变化；不能把ctime望文生义当作creation time。

p.34 的echo hello输出带换行，所以Size为6而不是5。**算一遍**：本例Blocks=8，以该stat接口使用的512字节计数单位解释（补充），分配占用8×512=4096字节；IO Block=4096是I/O提示尺寸，不能直接把Blocks=8再乘4096。文件逻辑长6字节与分配了4096字节并不矛盾。

## 目录与链接

### unlink提出的问题与目录创建（p.35–36）

> **p.35** Why it calls unlink() not “remove or delete”?

p.35 的问题先留住“名字与对象分离”这条线索：unlink取消一个名字连接，不保证立即销毁文件对象；p.39–43会用硬链接算清。p.36 的mkdir建立目录，逻辑上的空目录仍有`.`指自身、`..`指父目录。空指没有其他用户目录项，不是目录文件没有任何内容。

**补充**：创建权限还受进程umask影响，因此调用参数0777与ls显示的最终权限可能不同。

### 读取目录与删除空目录（p.37–38）

> **p.38** Require that the directory be empty

p.37 先opendir取得目录流，循环readdir逐项取得dirent，打印d_ino与d_name，最后closedir。目录流指针不是普通文件描述符整数；目录项提供的是名字与inode等目录层信息，完整元数据可另用stat获取。

p.38 的rmdir要求没有`.`、`..`以外的项；普通非空目录删除会失败。**补充**：readdir返回NULL还可能表示错误，应结合errno判别；不同文件系统可能不提供可靠d_type，所以需要类型时不能无条件只依赖这一个字段。

### 硬链接增加名字，不复制内容（p.39–41）【新】

> **p.40** The file is not copied in any way.

p.39 的ln file file2创建另一个名字，p.40说明它指向同一inode，p.41用两个相同的67158084验证这一点。因此没有一个在语义上更“原始”的名字；通过任一名字修改同一对象，另一名字看到的是同一内容。**补充**：跨文件系统仅比较inode数字不能判同一对象，还需要文件系统/设备身份。

**算一遍**：示例起初1个名字，link后2个名字、1个inode、1份数据。它不是2个inode各持1份内容，也不是文件大小因此翻倍。

### 链接计数与最后一次unlink（p.42–43）

> **p.42** When unlink() is called, the reference count decrements.

p.42 删除file后file2仍可读，回答了p.35：取消一个名字并不一定删除底层对象。p.43逐次增删名称：创建file后为1；ln file file2后2；ln file2 file3后3；rm file后2；rm file2后1；rm file3后0。

**补充**：课件以链接计数归零概括最终释放；若仍有打开引用，真实Unix文件通常还要等这些引用关闭才释放数据。链接数描述命名引用，不等于当前打开描述符数。进程可以在文件名被删后继续通过已打开fd访问它。

### 软链接存路径而不是给目标再添一个名字（p.44–46）【新】

> **p.45** A symbolic link holds the pathname of the linked-to file as the data of the link file.

p.44指出普通硬链接不能跨文件系统，也通常不允许链接目录；软链接用路径解决这些限制。p.45说明软链接是独立类型的文件，其数据是目标路径。路径解析时先看到链接，再沿所存路径寻找对象，因而多了一层解析。

**算一遍**：链接内容为file时长度4字节，不是目标文件的6字节；p.46改为alongerfilename，路径字符数15，所以链接长度15，目标文件仍为6字节。读软链接本身的属性与跟随它去读目标属性是两种查询，应检查工具或API是否跟随链接。

### 悬空软链接与接口总览（p.47–48）

> **p.47** When remove an original file, symbolic link points nothing.

p.47删除目标file后，软链接file2本身还在，但解析其存储路径失败，cat报告No such file or directory。它没有增加目标硬链接计数，因此不能像file2硬链接那样保住目标对象。

p.48的接口可按作用分组：open/read/write/lseek处理打开和字节位置；dup/pipe改变输入输出关系；fsync处理同步；rename/unlink/link处理名字；stat取元数据；目录流接口读取目录项。这样读接口序列，才能知道每行修改的是字节、偏移、描述符、名字还是持久化状态。

## 本讲核心考点

- 文件名、inode、打开状态、fd是不同层次（p.5–7，C 级通识考法）。
- dup共享打开状态；lseek改变该状态中的偏移（p.8–19，C 级通识考法）。
- 管道0读1写；EOF取决于所有写端引用关闭（p.20–29，C 级通识考法）。
- fsync与rename分别处理同步和名字切换（p.30–32，C 级通识考法）。
- 硬链接共享inode，软链接存目标路径（p.39–47，C 级通识考法）。
