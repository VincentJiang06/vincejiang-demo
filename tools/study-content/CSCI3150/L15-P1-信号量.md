## 从通知到可以留下的许可（p.1–3）

> **p.2** Race Conditions, Lock/Semaphore

## 先读懂课件采用的计数约定（p.4–6）【新】

> **p.4** An object with an integer value

p.4 的**信号量**（semaphore）有整数状态。`sem_init(&s, 0, 1)` 三项分别是对象地址、共享范围和初值。中间的 0 表示在同一进程的线程间共享。末尾的 1 表示开始时有一份可取得的许可。要改变用途，首先要问「开始时允许几次 wait 直接通过」。

p.5 的课堂模型让 `sem_wait` 原子地登记一次需求，计数减一。减完若非负，调用方可以继续；若为负，调用方等待。由 1 减到 0 的线程已拿到最后一份许可。由 0 减到 −1 的那个才需要睡。负值的**绝对值**是此模型中等待许可的线程数。后面 p.29–30 有另一种内部表示，在 Linux 中，sem_getvalue 对已有等待者的信号量返回当前值 0。课件表中的 −1 或 −2 不能直接当作该接口在 Linux 上的读数。[Linux 接口说明](https://man7.org/linux/man-pages/man3/sem_getvalue.3.html)

p.6 的 `sem_post` 登记一份新许可，计数加一；有等待者时唤醒一个。例如从 −1 到 0，刚归还的那份正好交给已经登记过需求的人。等它被调度回来，原来的 wait 完成，不再重复扣一次。没有等待者时 post 的效果会留在计数里。

## 一份许可怎样成为一把锁（p.7–9）

**原题｜L15 p.7 · Binary Semaphores (Locks)**

> **p.7** What should X be?

p.7 入口 wait，出口 post，临界区一次允许一人。取 X 为 1 能让第一个调用者立即进入；若为 0，所有人可能都停在入口，无人执行出口的 post；若大于 1，就可能放行多人。要维持互斥，每次成功进入只对应一次释放。

p.8 无竞争时，初值 1，T0 调 wait 后变 0，临界区执行期间一直是 0，post 后回到 1。表里「调用」和「返回」各占一行，两行合起来只算一次操作。

p.9 有竞争时按表依次记下五个值：1（初始）、0（T0 获得）、−1（T1 等待）、0（T0 释放并唤醒 T1）、1（T1 做完释放）。T1 从 sleeping 到 ready 的时刻还没有执行临界区；下一次被调度才从原 wait 返回。观察到 0 时要结合执行位置，不能一概读作「没人持有」。

## 完成通知为什么取初值零（p.10–12）

**原题｜L15 p.10 · A Parent Waiting For Its Child**

> **p.10** What should X be?

p.10 等待的是孩子完成一次打印。创建前尚无完成事件，所以 X 取 0。子线程先打印再 post，父线程先 wait 再打印结束。若初值为 1，父线程可以消费凭空多出的那份许可，抢先打印结束语。**补充**：课件示意代码的 pthread_create 首参写为 c，按 C 接口实际调用时应传保存线程标识的位置 `&c`。

p.11 父先到达：0 经父 wait 到 −1，父睡眠；子打印并 post 把值带回 0，父变为就绪，随后从 wait 返回。打印顺序为 `parent: begin → child → parent: end`。

p.12 子先到达：0 经子 post 到 1，此时唤醒人数为零，但有一份许可留存；父后来 wait 得到 0，直接继续。两条轨迹的终值和输出相同，中间是否实际发生阻塞则不同。这正是信号量与 L14 单独一次条件变量 signal 最好辨认的区别。

## 有多少空位，和谁在写同一槽，是两件事（p.13–15）【延伸 L14 p.46–48】

> **p.15** Imagine that MAX is greater than 1 .

p.13 环形数组的 put 先在 f1 写 `buffer[fill]`，再在 f2 推进写下标；get 从 use 取值并按容量回绕。即使生产者知道还有空位，它仍需要和其他生产者协调使用共享下标。

p.14 试用两个信号量。生产者 wait(empty)、put、post(full)，把一个空槽变成一个可取项目；消费者 wait(full)、get、post(empty)，方向刚好反过来。该版消费者遇 −1 才退出，节选没有展示结束标记的投放。它与后面按 loops 消费的版本有不同的结束条件。

p.15 空队列初始 `empty = MAX`、`full = 0`。**算一遍**（容量 2、数据 A 和 B 为自取）：两个生产者各拿一个空位许可，均可进入 put。第一个在 0 号位写 A，尚未推进 fill；第二个也在 0 号位写 B，A 被覆盖。即使后续两人各 post 一次 full，也不能凭两份许可变回两件有效数据。取许可与修改队列需分别保护。

## 把互斥加在外层会卡住谁（p.16–18）

> **p.18** The consumer still holds the mutex!

p.16 新增初值为 1 的 mutex 信号量，生产者先拿 mutex，再等 empty。该写法包住整个 put，避免上一页两人同时挑同一槽，但可能在还没有空槽时就抱着 mutex 睡着。

p.17 消费者镜像地先拿 mutex，再等 full。这里的 `sem_wait(&full)` 只操作 full，不像条件变量 wait 那样接收并释放关联锁。遇到空队列时，mutex 仍由消费者占着。

p.18 按原例让消费者先运行。它在 c0 拿到 mutex，在 c1 等待货物。生产者要放第一件货，却在 p0 等待消费者手里的 mutex。消费者要等生产者 post(full)，生产者要等消费者 post(mutex)，两方都到不了自己的 post。这是能从两条等待关系直接证明的死锁。

## 正确顺序与三个初值（p.19–20）

> **p.20** Adding Mutual Exclusion (Correctly)

p.19 生产者先 wait(empty) 预留一个空位，再 wait(mutex) 取得修改队列的权利。put 完毕，先 post(mutex) 放开临界区，再 post(full) 宣布有一件可取的数据。预留成功至 put 之前，其他生产者不能花掉自己的这份空位，仍可争抢其余空位。

**按 p.19–20 对照调用次序**，每列从上往下读。

| 阶段 | 生产者 | 消费者 |
|---|---|---|
| 预留资源 | `wait(empty)` | `wait(full)` |
| 进入队列临界区 | `wait(mutex)` | `wait(mutex)` |
| 改槽位和下标 | `put(i)` | `tmp = get()` |
| 退出临界区 | `post(mutex)` | `post(mutex)` |
| 通知另一类线程 | `post(full)` | `post(empty)` |

p.20 消费者先 wait(full)，再在 mutex 内 get，解锁后 post(empty)。空队列的三个初值依次是 MAX、0、1。重走 p.18：消费者现在第一步就睡在 full 上，mutex 仍然可用。生产者因此能放货、释放 mutex 并唤醒它。**补充**：一个线程取得 empty 而尚未发布 full 时，有一份许可在途，所以不能在任意指令处都断定 empty 加 full 恒等于容量。

## 第一位读者关门，最后一位读者开门（p.21–23）【新】

> **p.21** As long as we can guarantee that no insert is on-going, we can allow many lookups to proceed concurrently.

p.21 链表查找只读，多个查找可以同时进行；插入改变结构，需要独占。**读写锁**允许多读者同时通过，写者到来时要与所有读者及其他写者互斥。

p.22 讲义用两个初值均为 1 的信号量。lock 只保护读者数 readers 及读者群进出的过渡，writelock 控制共享数据的访问权。开始 readers 为 0。第一位读者要先取得 writelock，才能把整组读者带进去。

p.23 按一个完整过程读代码：R1 把 readers 从 0 加到 1，取得 writelock；R2 把 1 加到 2，直接加入。写者 W 此时等待 writelock。R1 离开把 2 减到 1，W 仍等；R2 把 1 减到 0，这个最后读者才 post(writelock)。读者增减在 lock 内串行，否则两个人可能都误判自己为「最后一个」。这里 writelock 是信号量，允许第一人与最后一人分别 wait、post。

## 写者饥饿与哲学家的两把叉（p.24–26）

**原题｜L15 p.24 · A Reader-Writer Locks**

> **p.24** How to prevent more readers from entering the lock once a writer is waiting?

p.24 读者陆续交接，readers 可以永远不降到 0。每个读者都读完，写者却一直拿不到 writelock。**补充解题**：在入口加一层公平排队，让已排到的写者把后来读者挡在门外；已经在读的人仍能退出，最后一人离开后写者进入。若入口本身允许无限插队，就不能由这个想法推出无饥饿保证。

p.25 圆桌图有五位哲学家和五把叉，相邻两人共享中间那把。吃饭必须同时持有左右两把，思考时一把都不需要。只知道总数够两个人吃，还不能决定哪两人能同时吃，要看叉是否重合。

p.26 给编号后，p 的左叉编号是 p，右叉是 `(p + 1) % 5`。例如 4 号的右叉绕回 0，所以 4 号与 0 号共享 0 号叉。要同时考察三件事：全桌能继续、每人最终能吃、不相邻的人能否并行吃。满足第一项不能推出后两项。

## 哲学家 4 换手后，等待环怎样消失（p.27–28）【新】

> **p.28** Let’s assume that philosopher 4 acquire the forks in a different order.

p.27 每把叉用一个初值 1 的信号量表示。若人人先拿左叉，0 到 4 号可以各自拿到同号叉，再各等右邻那把。0 等 1、1 等 2、2 等 3、3 等 4、4 又等 0。人人都到不了吃完后放叉的语句。

p.28 只有 4 号改为先拿右叉 0，再拿左叉 4。现在五人的拿叉顺序都是编号递增，例如 3 再 4、0 再 4。若有环，沿着等待方向叉号必须严格增加一整圈又回到原数，这是不可能的。该证明消除环形死锁，是否饥饿仍取决于竞争与调度。<a name="r-a1"></a>[见附录 A1](#a1)。

## 用锁和条件变量造一个信号量（p.29–30）

> **p.30** The value should never be lower than zero.

p.29 自制的 Zemaphore 把 value、mutex、CV 放在同一个对象中。wait 先拿锁，value 为 0 时在 while 内进行条件等待；醒来重获锁，亲自确认有许可再减一。这样两个竞争线程读到的可消费许可不会重复，同一对象只应初始化一次。

p.30 post 在锁内加一并 signal。从 0 开始，两个等待者都会睡，而 value 仍是 0。post 一次后 value 暂为 1，有一个线程成功消费后变回 0。p.5 的模型会把两个挂起的需求记为 −2，这里让 CV 队列记录等待者。两者在「没有许可时不能通过」这一外部行为上一致。

## 本讲核心考点

- 由要表达的资源决定初值，并跟踪谁先 wait 或先 post（p.4–12，C 级）。
- 指出消费者先取得 mutex 再等 full 的死锁链，写出正确次序（p.13–20，C 级）。
- 用读者数的两次边界变化解释写者阻塞和饥饿（p.21–24，C 级）。
- 从叉号证明改变 4 号顺序可断环，区分断环和公平（p.25–28，C 级）。
