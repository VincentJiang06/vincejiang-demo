## 从接口进入磁盘上的结构

### 两个互相配合的问题（p.2–3）【新】

> **p.3** There are two different aspects to implement file system

p.2 把本讲移动到Persistence中的File System。p.3要求同时回答：数据和元数据放成什么结构，以及一次open/read/write会访问其中哪些结构。前者是静态布局，后者是动态路径。只画出inode却不能说明怎样从文件名找到它，还没有解释完整文件系统。

### 分块、数据区与inode区（p.4–6）

> **p.4** Block size is 4 KB.

p.4将示例磁盘分成0–63号块。这里的4KB按图中地址计算采用4096字节，因此全盘64×4096=262144字节。p.5把8–63号的56块保留为数据区，共56×4096=229376字节；还必须留下记录这些数据属于谁的元数据。

p.6把3–7号块分给inode表，共5块，每个inode为256字节。**算一遍**：每块4096÷256=16个inode，5块共80个。80限制可记录的对象数量，并不表示有80个数据块；目录也需要inode，空文件也可能占用inode但没有文件数据块。

图（p.4–6）：磁盘块布局逐步成形
元素：64个格子，块8–63标D，块3–7标I，块1/2预留位图。
看什么：区分存对象属性的inode区和实际承载内容的数据区。

### 两张位图与超级块（p.7–8）

> **p.7** Use bitmap, each bit indicates free(0) or in-use(1)

p.7用inode bitmap记录哪些inode已用，用data bitmap记录哪些数据块已用。分配inode与分配数据块是两种独立资源，不能只查其中一张表。**算一遍**：80个inode至少需80位即10字节；56个数据块至少需56位即7字节。本教学布局仍给每张位图整整一个4KB块，简单布局的预留空间不等于最小信息量。

p.8在块0放superblock，记录inode数量、inode表起点等全局参数。挂载先读它，才能知道其他结构在哪，而不是把某张图上的固定偏移当所有文件系统的通用常量。

### 从inode号算到扇区（p.9–10）【新】

> **p.9** Each inode is referred to by inode number.

p.9给定inode号32，inode表起点12KB，每项256字节。先把对象编号转换成表内字节偏移，再加表起点；p.10再把磁盘字节位置转换为512字节扇区号。公式按讲义重排：

$$
\begin{aligned}
o &= 32\cdot256=8192,\\
a &= 12\cdot1024+8192=20480,\\
b &= \lfloor8192/4096\rfloor=2,\\
s &= (2\cdot4096+12288)/512=40.
\end{aligned}
$$

o是inode表内偏移，a是该inode的磁盘字节地址，b是相对inode表的块序号，s是该块起始扇区号。本例32恰好落在块首，所以对象地址与块首地址相同；一般inode还需要块内偏移，不能把两者始终等同。完整定位顺序<a name="r-a1"></a>[见附录 A1](#a1)。

### 直接、一级与多级间接索引（p.13–15）【新】

> **p.13** Indirect pointer points to a block that contains more pointers.

p.13的直接指针直接给出数据块号，间接指针先指向一个“装块号的块”。4KB索引块、每个块号4字节，可装4096÷4=1024个块号。12个直接指针加一个一级间接指针可覆盖(12+1024)×4=4144KiB文件内容；索引块本身不算文件内容。

p.14二级间接需要先读一个装“一级索引块号”的块，再读选中的一级索引块，才得数据块号；覆盖1024×1024个数据块。三级再多一层。12直接+一级+二级覆盖(12+1024+1048576)×4096=4299210752字节，略大于4GiB。这里算可寻址内容容量，不是整个文件连元数据的总物理占用。

图（p.14）：多级索引关系
元素：文字明确区分single、double、triple indirect，二级指向间接块，三级指向二级块。
看什么：每多一级，多一次索引选择，也多一层可覆盖的块集合。

p.15的测量表解释混合设计：多数文件小，而多数总字节由少量大文件占据。小文件用直接指针节省间接访问，大文件需要时再分配索引块。原表还报告典型小文件约2K、平均接近200K、文件系统平均约100K个文件、约半满、很多目录20项以下；这些是讲义引用的历史测量，不能当作今天所有工作负载的统计规律。

p.17给出的解法先除4096。起始逻辑块a是offset除4096向下取整；最后一个字节是offset+count−1，因此最后逻辑块也要向下取整。逻辑块0/1查直接指针，逻辑块a≥2查Cell[a−2]。物理块号不要求连续，不能把第一个物理块号一路加一。

**算一遍**：(i)开始7000÷4096取整为1，结束字节15999所在逻辑块为3，所以读逻辑块1、2、3，映射为96、146、198；135是索引块，题目明确只列数据块，因此不写进答案序列。(a)容量为(2+1024)×4096=4202496字节。所有六个请求的逐步计算和实际覆盖字节<a name="r-a2"></a>[见附录 A2](#a2)。

**考试角度**：（C 级 通识）常见考法是同时求最大文件容量、逻辑块区间和物理块序列；索引块I/O次数与题目要列的数据块序列必须分开。

**补充：把“寻址容量”与“真正读了哪些块”分开。** inode 的直接指针直接给出文件数据块号；一级间接指针先给出一个保存块号的索引块，再从里面取数据块号。索引块本身不属于文件的用户数据，所以容量只计算可寻址的数据块，不能把索引块的 4096 字节加进文件内容容量。

沿 p.16–17 的两直接块例子，逻辑块 0、1 从 inode 直接取；逻辑块 2 对应间接表 Cell0，逻辑块 3 对应 Cell1。因此表下标是“逻辑块号减 2”，不是照抄逻辑块号。读跨块区间时先在文件逻辑字节空间切分，再把每个逻辑块映射到物理块；物理块可能不连续，不能从第一个物理块号开始简单加一。

题目若改问磁盘 I/O 次数，还需加入未缓存的 inode、索引块等读取。若同一间接表已经在内存里，后面多读一个数据块未必再读一次索引块。先确定题目要的是数据块序列、总寻址容量还是冷缓存 I/O，三个问题的数字可以不同而都正确。

>
> Assume the inode numbers of “/”, “dir1”, “dir2”, “file1” are 0, 1, 2 and 3, respectively. Moreover, each directory file only occupies one data block (4 KB for one data block), and the data block numbers allocated to “/”, “dir1” and “dir2” are 0, 1 and 2, respectively.
>
> Suppose a user provides the following absolute path: /dir1/file1
>
> In order to obtain the inode number of file1, the sequence of the inode numbers and the data block numbers we need to pass (starting from the root directory)

图（p.19）：/下有dir1与dir2，dir1下有file1
元素：根inode0，dir1 inode1，dir2 inode2，file1 inode3；三目录的数据块分别0、1、2。
看什么：inode给出目录数据块位置，数据块内名字映射给出下一inode号，两种编号交替出现。

**算一遍**：Block0是根的目录内容，记录`.`→0、`..`→0、dir1→1、dir2→2。根的父仍是根，故前两个值都为0。查/dir1/file1：inode0→数据块0，找dir1得到inode1→数据块1，找file1得到inode3。取得inode号到此结束；若题目要求读取文件内容，才继续读inode3及其数据块。

### 分配位图与路径读取（p.20–22）

p.20创建对象时先搜索inode位图，找到空位并标已用；分配数据又查数据位图。预分配连续块可让后续增长更容易获得连续空间，但分配仍要维护正确的已用状态。

p.21的open(/foo/bar)从根inode开始，读根数据查foo，再读foo inode与目录数据查bar，最后读bar inode并检查权限、建立描述符。不要从路径字符串中的字符位置直接推磁盘位置。p.22 read依据inode找到数据块、更新内存中的打开偏移；讲义模型还更新访问时间。close释放描述符，本简化模型无需新增磁盘I/O。**补充**：缓存、时间戳策略和延迟写会改变实际系统的物理I/O数量，必须先说明采用哪个模型。

### 读时序图怎样计数（p.23）

图（p.23）：File Read Timeline，时间向下
元素：root/foo/bar的inode列、目录数据列和bar的三个数据块列；open有5次读，每次read有inode读、数据读、inode写。

### 写与创建为何涉及更多元数据（p.24–25）

> **p.24** It generates five I/Os:

p.24新增一个文件数据块时，读写数据位图各1次，读写inode各1次，写数据块1次，合计5。若只覆盖已分配块，未必需要新的分配位图操作；创建新名字还要修改目录。

图（p.25）：创建/foo/bar再写三个数据块
元素：创建阶段读root inode/data、foo inode/data，读写inode bitmap，写foo data，读写bar inode，写foo inode；每个write阶段包含数据位图读写、bar inode读写与数据写。
看什么：目录保存名字，inode保存对象状态，位图保存分配状态，三者要一起更新。

**算一遍**：依图创建阶段6读4写=10次；随后每个write为2读3写，三个共15次；合计25次。这个数字是该教学时间线的模型计数，不是任意create系统调用的硬性成本。

**补充：创建为什么不能只写新文件内容。** 想让路径 `/foo/bar` 表示一个新文件，至少要维护四种事实：哪个 inode 归它；哪个目录项把 bar 映射到该 inode；哪些数据块归它；inode 中的大小和指针如何描述这些块。位图只回答“是否已被占用”，不会自动生成目录项；目录项只回答“名字找到哪个对象”，也不会自动初始化数据块。

把 p.25 的写入流程当作一次多对象状态改变，就能看出崩溃一致性问题。若先让目录项指向尚未初始化的 inode，掉电后名字可能连到无效状态；若先分配了空间却没来得及把它接入可达结构，可能遗留无法正常找到的占用。这是本讲访问路径继续通向日志/恢复机制的原因。这里解释风险，不把本页简化顺序宣称为完整的崩溃安全协议。

:::hint 自测：文件只有 6 字节，为什么还会占一整块，并需要 inode 与目录元数据？

第一层：分配粒度是块，逻辑长度则按字节记录；块中未用部分不计入文件长度。

第二层：6 个内容字节不能独自说明文件名、权限、数据位置和占用状态。这些额外信息也需存储。计算题应明确是否只问数据区占用，还是把元数据一起计费。

:::endhint

### 缓存与延迟写解决不同瓶颈（p.26–28）

p.26指出长路径的每级都可能读inode与目录数据，缓存能免去重复读。统一页缓存动态分享内存，比固定分区更能适应当前需求。p.27则指出最终需要持久化的数据仍要写到盘，但写缓冲可以合并多次修改、重排I/O，甚至取消最终不再需要的中间写。

**算一遍（补充；数字是我为演示取的，讲义没给）**：同一块在刷盘前被更新10次，若每次同步写是10次写；若只需最后状态且允许缓冲，可能合为1次。减少的是中间版本的物理写，并不免除最终持久化义务。p.28收束为数据结构、访问路径与缓存三条线。

## 本讲核心考点

- 分配位图区分inode与数据块两种资源（p.4–8，C 级通识考法）。
- inode32位于字节20480、块起始扇区40（p.9–10，C 级通识考法）。
- 间接索引容量取决于块尺寸与块号尺寸（p.13–17，C 级通识考法）。
- 路径查找交替经过inode与目录数据（p.18–23，C 级通识考法）。
- 读写I/O数量必须先固定缓存与时间戳模型（p.23–27，C 级通识考法）。

### A2 SFS最大容量与六次跨块读取（p.16–17）

<a name="a2"></a>页内每个块号4字节，因此一个4096字节间接块存1024个指针；两直接块加这1024块，容量为1026×4096=4202496字节。这里只受寻址结构限制；实际文件还受磁盘空闲量等条件约束。

| Example 1 | 667 | 0 | 268 | 0 | 667 | 78 |
| Example 2 | 6267 | 0 | 268 | 1 | 2171 | 78,96 |

| (ii) | 39999 | 3 | 2712 | 9 | 3135 | 198,235,236,237,315,369,444 |
| (iii) | 55999 | 4 | 3616 | 13 | 2751 | 235,236,237,315,369,444,455,569,678,679 |
| (iv) | 21999 | 0 | 1000 | 5 | 1519 | 78,96,146,198,235,236 |

(i)：7000=1×4096+2904，15999=3×4096+3711；首块1192字节、中间块4096字节、末块3712字节，共9000。逻辑1直接取96；逻辑2/3查Cell0/1，得到146/198。
