## 让CPU份额服从权重

### 票数表示相对份额（p.35–36）【新】

> **p.35** Not optimized for turnaround or response time

p.35切换目标：比例份额关注各任务取得多少CPU，而非首先让某个任务结束或响应。p.36中A75票、B25票，总100，因此目标份额A=75/100=75%，B=25%。票数是相对量：所有票同时翻倍，比例不变；仅一个任务增加票数则所有人的分母也变了。

### 抽签的短期结果与票币换算（p.37–38）

**题面**（同原件 · Lottery scheduling · p.37）

> **p.37** There are 100 tickets

> **p.37** Process A has 75 tickets: 0 ~ 74

> **p.37** Process B has 25 tickets: 75 ~ 99

> **p.37** Scheduler’s winning tickets: 63 85 70 39 76 17 29 41 36 39 10 99 68 83 63

逐个比较中奖号：小于75为A，75–99为B，得到A B A A B A A A A A A B A B A。**算一遍**：A出现11次，B4次，实际份额11/15≈73.33%与26.67%；目标75/25不要求每个有限窗口都精确相等。票数决定每次概率，长时间统计才更接近期望。

p.38中用户A和B各有100全局票。A内部给A1/A2各500本地票，先算内部比例500/1000=1/2，再乘100，各50全局票；B内部10票全部给B1，因此B1仍取得100全局票。不能跨用户直接比较500与10，否则混淆不同币值单位。

### 转移、膨胀与累计区间实现（p.39–40）

p.39允许临时转票，表达把自己的份额交给另一任务；票数膨胀则临时增减权重。**补充**：膨胀需在可信管理规则下使用，否则任务自行无限增票就破坏公平。

p.40链表A100、B50、C250，总400。遍历累计边界100、150、400，选第一个严格大于中奖号的节点。**算一遍**：winner=120（数字是我为演示取的，讲义没给），A累计100不大于120，继续；B累计150>120，选B。合法中奖整数为0–399；若随机函数包含400而算法还用严格大于，则没有节点命中，边界必须统一。

```text
从0至总票数减1均匀抽一个整数
累计票数从0开始
依次加入每个任务票数
第一次累计值大于中奖号时选中该任务
```

### 公平指标与样本长度（p.41–42）

> **p.41** The time the first job completes divided by the time that the second job completes.

本页正文是位图，已视觉读取。两个等长作业各需10，若分别在10和20完成，U=10/20=0.5；若接近同时结束，U接近1。名称虽为unfairness metric，方向却是越接近1越公平，不能按单词直觉把0解释成最好。

图（p.42）：平均U随作业长度增加
元素：横轴Job Length约1–1000、纵轴Unfairness (Average)约0–1，曲线由约0.5上升至接近1。
看什么：短作业抽签次数少，随机波动更明显；长期比例正确不等于短期完成时刻公平。

**补充：概率、份额和完成时刻分别是什么。** A 有75%的票，表示在每次按相同票池均匀抽签时，A 中签概率为0.75。若连续四次都选A，这一具体事件的概率为 $0.75^4=0.31640625$；因此“四片里一定给B一片”不是彩票算法的承诺。这里假设各次独立抽签、任务一直可运行、票数不变，是为解释随机波动自取的窗口。

份额还取决于计量单位。如果中奖者每次运行的片长相同，获奖次数可近似代表 CPU 服务；若有的任务提前阻塞，单数中奖次数不能直接当实际CPU时间。原表默认的可比较片长是算比例的前提。

Stride 用虚拟进度代替抽签：权重大者每运行一次只走较小一步，因此会较频繁地落在最小 pass 一侧。pass 不是已经运行的真实毫秒数；不同权重下，同样一片加的 pass 不同。每次选择前比较旧 pass，选择后只更新该任务，才能复现 p.44 的表。

:::hint 自测：所有票数乘二后，彩票中奖份额会翻倍吗？Stride 步长又如何？

份额不变，因为分子、分母同时乘二。若固定 K，stride=K/票数会全部减半；各任务之间的相对步长不变，在相同平局规则和精确算术下仍表达相同份额。实现若整数取整，则需另检查舍入误差，不能把数学比例直接等同于任意代码实现。

:::endhint

## 用确定性步长接近比例

### Stride与pass（p.43–44）【新】

> **p.43** Pick the process to run that has the lowest pass value

stride是每运行一片增加的虚拟进度，设常数K=10000，A100票得到100，B50票得到200，C250票得到40。票越多，步子越小，因而更快再次成为最小pass。每次只增加被选者的pass，不把所有任务都加一次。

表（p.44）：课件的运行前pass与选择

| A的pass | B的pass | C的pass | 运行 |
|---:|---:|---:|---|
| 0 | 0 | 0 | A |
| 100 | 0 | 0 | B |
| 100 | 200 | 0 | C |
| 100 | 200 | 40 | C |
| 100 | 200 | 80 | C |
| 100 | 200 | 120 | A |
| 200 | 200 | 120 | C |
| 200 | 200 | 160 | C |
| 200 | 200 | 200 | … |

**算一遍**：8片内A2次、B1次、C5次，比例2:1:5，与100:50:250相同；同pass时按表给出的顺序打破平局。若老任务pass都200，新任务从0开始且stride40，则先跑5次才追到200，这解释新任务零初始化为什么可能暂时独占。**补充**：实际加入策略要与当前虚拟进度对齐，不能一律从零开始。

**考试角度**：（C 级 通识）常见考法是给票数手算随机中奖区间或stride表，并解释随机公平和确定性比例的差别。

## 本讲核心考点

- 份额=自身票数/总票数（p.35–38，C 级通识考法）。
- Lottery短期可偏离目标比例（p.37、41–42，C 级通识考法）。
- 本地票币先换为全局权重（p.38，C 级通识考法）。
- Stride选最小pass，运行后仅给选中者加stride（p.43–44，C 级通识考法）。
