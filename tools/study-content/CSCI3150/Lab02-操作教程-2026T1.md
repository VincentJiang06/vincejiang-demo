## 3. 先运行教学示例，观察四件事

在**容器终端**执行：

```sh
cd /work/Lab02
gcc -std=c99 -Wall -Wextra -Werror -pedantic concept_demo.c -o /tmp/lab2-concepts
lab2_demo_dir=$(mktemp -d /tmp/lab2-concepts.XXXXXX)
cd "$lab2_demo_dir"
/tmp/lab2-concepts 6
```

使用临时工作目录，是因为示例会生成 `seek-demo.bin`。它不会修改练习的 input.txt 和官方样例。主源码在 [concept_demo.c](课程工作目录/CSCI3150-Lab1/Lab02/concept_demo.c)。

实测输出：

```text
sizeof(int)=4 sizeof(pointer)=8
n=6 VLA_bytes=24 heap_bytes=24
0 2 4 6 8 10
after write offset=20
read1=20 text=Hello World!
read2=14 text=World!
bookA=1 bookB=3
```

按顺序观察：

1. **指针和对象大小不同**。p 自身是 8 字节，但它指向的六个 int 是 24 字节。不要用 sizeof(p) 代替数组长度。
2. **先分配，再初始化，再使用，最后释放**。循环填入 i×2；malloc 本身没有生成偶数，也没有清零保证。
3. **文件偏移不是内存指针**。写 20 字节，偏移到 20；seek 回 0 后读 20；seek 到 6 后只剩 14 字节。World! 的起点是下标 6。
4. **值副本与原对象不同**。改变副本后 bookA 仍是 1；通过地址修改后 bookB 变成 3。示例给对象补了初值，避免直接照抄原页未初始化对象。

再执行 `/tmp/lab2-concepts 3`，前面的数组变成 12 字节和 `0 2 4`；后面的文件与结构体部分不变。这两种参数都已在原容器实际运行，并通过严格编译选项。它验证的是教学例子，不是 exercise.c 的正确性。

## 5. 两条接口路线分别怎样理解

| 步骤 | stdio 路线（公告允许） | POSIX 路线（公告允许） |
|---|---|---|
| 输入打开 | fopen 的 r 模式 | open 的 O_RDONLY |
| 读入 | fscanf 成功转换一个整数 | read 获取字节，再拼完整行 |
| EOF | 以转换返回值控制，区分 ferror | 正请求量的 read 返回 0 |
| 数值转换 | fscanf 的格式负责 | 完整行用 sscanf 或其他合适转换 |
| 输出打开 | fopen 的 w 模式 | O_WRONLY、O_CREAT、O_TRUNC 与创建 mode |
| 输出 | fprintf 写两个数与换行 | 格式化文本，write 写足字节 |
| 关闭 | fclose，并检查结果 | close，并处理失败 |

stdio 的 `%d` 需要整数变量的地址，例如 `&value`；它返回成功转换项数，不是读入的整数值。不能把 `fscanf(...)` 返回的 1 当作输入数值累加。该方法依赖题目“一行一个整数、输入有效”的保证；空行等未规定格式不靠它自动保留物理行号。

POSIX 的 read 不懂整数，也不保证停在换行。若块末尾只有字符 `1`，不能马上当成数值 1；下个块可能以 `2` 开头，组合后本来应是 12。应保留半行，直到看到行终止符或最后 EOF。write 的返回值也可能小于请求量，需要继续写剩余部分。

两个路线最终算法相同，但文件接口和解析责任不同。任选一条完整路线即可，没有同时使用所有函数的要求。对这个按整数读取并求和的练习，stdio 路线需要手动处理的解析细节更少。


本 ZIP 的样例行尾是 CRLF。上面仅在比较副本中去掉行末 CR；不改原件、不删除普通空格，也不掩盖额外输出行。diff 无输出且退出码为 0 表示此样例文本匹配。样例通过不等于隐藏测试通过。

若希望检查原始字节，用 `od -An -tx1 output.txt`。正常的 Linux 两行文本可写为 `43\n42\n`，对应十六进制 `34 33 0a 34 32 0a`。不要把字符串结尾的 NUL 字节额外写入结果，也不要输出“odd sum:”之类标签。

## 8. 常见现象该查哪里

| 现象 | 先查 |
|---|---|
| No rule to make target exercise.c | 是否只有 exercise_skeleton.c，还未建立工作文件 |
| 找不到 input.txt | 当前目录是否含输入；运行位置而非源码位置决定相对路径 |
| 输出是按数值奇偶分组 | 分支条件是否错误使用 value 的余数，而非行号或轮换状态 |
| 最后一个数加了两次 | 是否用 feof 预判，再忽略读取结果 |
| read 版本把 12 拆成 1 和 2 | 是否把块边界误作行边界 |
| 输出后面残留旧内容 | 是否缺少截断模式，或误用追加模式 |
| 样例通过是否就完成了 | 两套接口均获公告允许；仍需检查不同输入长度、EOF 处理、按行分组和两行输出，不能只验证给定样例 |
