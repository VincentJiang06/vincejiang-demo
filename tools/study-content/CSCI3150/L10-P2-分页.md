## 逐页伴读

p.18 是 Part II 标题。

### p.19–21：页连续，页框可以散开

> **p.19** Paging splits up address space into fixed-sized unit called a page.
>
> Segmentation: variable size of logical segments(code, stack, heap, etc.)
>
> With paging, physical memory is also split into some number of pages called a page frame.
>
> Page table per process is needed to translate the virtual address to physical address.

虚拟空间按固定页长切为 page，物理内存按同样大小切为 frame。每个进程的页表记录“我的第几页放在哪个物理框”，所以不同进程的同一 VPN 可以有不同映射。

图 p.20–21 用三种颜色代表 P1、P2、P3，箭头把各进程的虚拟页连到物理框；要看虚拟顺序与物理顺序无须一致。p.21 的页表逐列读取：P1 的 VPN 0–3 分别映射 3、1、7、10；P2 映射 0、4、2、6；P3 映射 8、5、9、11。三者恰好各占四框，合计十二框，没有重复占用。不能把横向相邻的表格项当成同一进程。

### p.22–24：页号和页内偏移各管什么

> **p.22** Flexibility: Supporting the abstraction of address space effectively
>
> Don’t need assumption how heap and stack grow and are used.
>
> Simplicity: ease of free-space management
>
> The page in address space and the page frame are the same size.
>
> Easy to allocate and keep a free list

> **p.23** 128-byte physical memory with 16 bytes page frames
>
> 64-byte address space with 16 bytes pages

> **p.23** (page 0 of                            the address space)

> **p.23** 64-Byte Address Space Placed In Physical Memory

> **p.23** page frame 0 of                           physical memory

> **p.24** Two components in the virtual address
>
> VPN: virtual page number
>
> Offset: offset within the page
>
> Example: virtual address 21 in 64-byte address space

原例：虚拟空间 64 B，页长 16 B，物理内存 128 B；映射为 VPN 0→PFN 3、1→7、2→5、3→2。共有 4 个虚拟页、8 个物理框。虚拟地址 6 位，其中页内偏移 4 位，VPN 2 位；物理地址 7 位，其中 PFN 3 位。

图 p.23 物理框 0 留给 OS，未用框与已映射框交错。分页的简单之处是任何空闲框都能接纳一个页，不必寻找能容纳整个进程的连续区域。它仍可能有页内部没用完的空间，不能说完全没有碎片。

### p.25–27：把 21 转成 117，再问页表放哪里

> **p.25** The virtual address 21 in 64-byte address space

> **p.27** Example: Page Table in Kernel Physical Memory

题面沿用上节映射，求虚拟地址 21 对应物理地址。先做除法：$21=1\times16+5$，故 VPN=1、offset=5；页表得到 PFN=7，最终 $7\times16+5=117$。二进制就是 `01 0101` 换成 `111 0101`，低四位原样保留。

图 p.27 在物理框 0 内写入页表 `3 7 5 2`。页表本身也占真实存储，通常不能全塞进少量寄存器。p.26旧PDF兼容图片误显调度例子；PPTX正文层实际说明32位地址、4KiB页、20位VPN、每项4B，页表共4MiB，并存放在内存中。以下根据原件正文层完整展开，通用公式是：

$$
N_{PTE}=\frac{2^{VA\_bits}}{page\_size},\qquad size_{PT}=N_{PTE}\times size_{PTE}.
$$

**原件 p.26 算例**：32 位虚拟地址、4 KiB 页、每项 4 B，页数为 $2^{32}/2^{12}=2^{20}$，线性页表占 $2^{22}$ B=4 MiB。进程即使只用了几页，平铺整张表仍付出这份空间。

**补充：页内偏移为什么原样保留。** 转换只替换“这一页存放在哪一框”，不改变页内部字节的相对顺序。p.25 的 VA21 是 VPN1 的第5号字节；无论这一页放到哪个框，仍须访问那个框的第5号字节，所以把PFN7乘16得到框起点112，再加5到117。若把offset也查表或重新缩放，就不再访问原来的那个字节。

最后一个页内字节是offset15。VA31=1×16+15，映射为127；下一个VA32=2×16+0，却映射到PFN5的起点80。虚拟地址只加1，物理地址却可以跳到较小位置，因为跨越了页边界。这个例子沿用原映射，说明不能用第一字节物理地址加长度替代跨页访问的逐页转换。

### p.28–30：PTE 除了框号还需要状态

> **p.28** The page table is just a data structure that is used to map the virtual address to physical address.
>
> Simplest form: a linear page table, an array
>
> The OS indexes the array by VPN, and looks up the page-table entry.

> **p.29** Valid Bit: Indicating whether the particular translation is valid.
>
> Protection Bit: Indicating whether the page could be read from, written to, or executed from
>
> Present Bit: Indicating whether this page is in physical memory or on disk(swapped out)
>
> Dirty Bit: Indicating whether the page has been modified since it was brought into memory
>
> Reference Bit(Accessed Bit): Indicating that a page has been accessed

最简单的线性页表是数组，VPN 就是数组下标。Valid 表示映射是否合法；Present 表示合法页当前是否驻留物理内存，二者不能互换。合法但不驻留的页可能需要换入，不是非法地址。

Protection 控制读写执行；Dirty 表示换入后被改写，决定淘汰时是否需要写回；Accessed/Reference 记录近期访问，供置换参考。图 p.30 的 x86 PTE 高位存 PFN，低位存标记，具体硬件位义应按该图解释，不能把所有体系结构都当成这张格式。

**把 p.30 的 32 位 PTE 位图写成表。** 位号从右端 0 数到左端 31；连续的 PFN 占 20 位，组合 12 位页内偏移即可形成该例的 32 位物理地址。

|位号|原图标签|本节如何使用|
|---|---|---|
|31–12|PFN|目标物理页框号|
|11–9|无标签蓝色区域|原页未给用途，不能把它们算入 PFN|
|8|G|原图列出的全局属性位|
|7|PAT|原图列出的缓存属性位|
|6|D|Dirty，记录写入|
|5|A|Accessed，记录访问|
|4|PCD|原图缓存控制标签|
|3|PWT|原图缓存控制标签|
|2|U/S|用户／特权访问控制；原页简写为 supervisor|
|1|R/W|读写控制|

### p.31–33：一次访存为什么可能变成两次

> **p.31** To find a location of the desired PTE, the starting location of the page table is needed.
>
> For every memory reference, paging requires the OS to perform one extra memory reference.

**课件程序与接口（p.32，原页片段）**

```text
1   // Extract the VPN from the virtual address
2   VPN = (VirtualAddress & VPN_MASK) >> SHIFT
3
4   // Form the address of the page-table entry (PTE)
5   PTEAddr = PTBR + (VPN * sizeof(PTE))
6
7   // Fetch the PTE
8   PTE = AccessMemory(PTEAddr)
9
10  // Check if process can access the page
11  if (PTE.Valid == False)
12      RaiseException(SEGMENTATION_FAULT)
13  else if (CanAccess(PTE.ProtectBits) == False)
14      RaiseException(PROTECTION_FAULT)
15  else
16      // Access is OK: form physical address and fetch it
17      offset = VirtualAddress & OFFSET_MASK
18      PhysAddr = (PTE.PFN << PFN_SHIFT) | offset
19      Register = AccessMemory(PhysAddr)
```

> **p.33** Segmentation
>
> A program contains logically-different segments: code, stack, heap
>
> Each segment can be placed in different part of physical memory.
>
> Base and bounds exist per each segment.
>
> Paging
>
> physical memory is split into some number of pages called a page frame.
>
> Page table per process is used to translate the virtual address to physical address.
>
> Next: Free Space Management, Translation Lookaside Buffers, Advanced Page Tables, and Swapping (Chapters 17, 19, 20, 21, 22, 23)

页表起始物理地址 PTBR 加上 `VPN*sizeof(PTE)` 得到的是 **PTE 的地址**，读取 PTE 才得到 PFN。检查合法性和权限后，再将 PFN 与偏移组成最终物理地址，读取目标。

无 TLB、无缓存命中的简化模型中，一次数据访问变成“读 PTE＋读数据”两次物理访问。课件 p.31 用 OS 概述管理责任；p.32 的正常硬件转换不意味着每次访问都陷入内核执行软件。下一讲的 TLB 正是缓存转换结果，省掉反复读页表的代价。

p.33 回看两个设计：分段贴近逻辑区域但可变长；分页固定长度，便于分配，但页表可能又大又慢。不要只记分页优点而漏掉新成本。

:::hint 自测：PTBR=1000、VPN=3、PTE大小4字节，算出的1012是什么？

第一层：1012是页表中第3项的存放地址，不是用户数据地址。这里数字是自取的地址算术示意。

第二层：还要读取该项、检查状态与权限、取得PFN，然后用PFN乘页长再加原虚拟地址的offset。若没有PTE内容，无法给出最终物理地址。把1012直接作为目标，是少走了一次“读取指针所指内容”的间接层。

:::endhint
