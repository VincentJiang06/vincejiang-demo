### 归并排序与每层成本（p.5–6）【新】

**题面**（L02-Divide-and-Conquer-未核.pdf · Sorting · p.5）

> **p.5** Problem: Given an array A of n distinct integers, produce another array where the same integers have been arranged in ascending order.

p.5 按**原数组位置**分成前后两半，再递归排序。合并时只比较两半尚未输出的第一个元素，输出较小者并推进其指针。为什么不必看后面的元素？每半已经有序，后面不可能比其首个剩余元素更小。

**补充／算一遍**（数字是我为演示取的，讲义没给）：合并 `[2,7]` 与 `[3,5]`：2 与 3 比，输出 2；7 与 3 比，输出 3；7 与 5 比，输出 5；右半空，追加 7。结果 `[2,3,5,7]`，每个元素只输出一次，线性合并。

**补充：合并循环的不变量。** 已输出的前缀始终有序，且恰好包含两半中已经取走的那些最小元素。初始前缀为空，性质成立。两半各自有序，剩余所有元素的最小者必在两边当前头部之一；取两者较小值，不会把更小的未输出元素留在后面，性质因而继续成立。某半为空后，另一半已有序，直接追加即可。结束时每个输入元素恰被取走一次，才同时得到“有序”和“不丢不重”两个正确性条件。

原演示的状态如下；`i,j` 是已经从左右各取走多少个元素：

| i,j | 已输出 | 下一步 |
|---|---|---|
| 0,0 | 空 | 取左边 2 |
| 1,0 | 2 | 取右边 3 |
| 1,1 | 2,3 | 取右边 5 |
| 1,2 | 2,3,5 | 右半耗尽，追加 7 |

一次循环至少消耗一个元素，因此总迭代不超过两半长度之和；不能因为循环内有左右两支，就把成本再乘一次 n。通常实现使用一块长度 n 的辅助数组；递归调用总数多，并不要求为所有历史调用永久保留各自的副本。

:::hint 自测：若输入允许重复，合并时相等取哪侧？

单为数值有序，任选一侧均可。若还要求稳定排序，即原来同值元素的先后次序不变，应先取左侧，因为左侧来自更早的原位置。稳定性是附加规格，讲义的互异输入没有这个歧义。

:::endhint

> **p.6** $f(n)\le 2\cdot f(\lceil n/2\rceil)+O(n)$

公式按讲义重排。p.6 的两个递归调用都要计费。忽略取整来看，第 $j$ 层有 $2^j$ 个规模 $n/2^j$ 的问题，所以合并总量为 $2^j\cdot n/2^j=n$；约 $\log_2 n$ 层，得到 $O(n\log n)$。演示 $n=8$ 时，三层合并工作量分别是 8、8、8，而不是只计算根节点的 8。

<a name="a4"></a>**题面**（Midterm-2021T1-题目.pdf · Q2(b) · p.1）

> **p.1** “(b) Consider a divide-and-conquer algorithm A to solve a problem: divide an instance I of size n into k subinstances of size n/t in time O(n), and then combine solutions of subinstances in time O(n) to obtain a solution for I. Determine value of (k, t) to make A run as fast as possible.”
>
> “(1) (3, 2) (2) (4, 2) (3) (8, 4) (4) (9, 3) (5) (12, 6).”

递推为 T(n)≤kT(n/t)+cn。第 j 层 kʲ 个问题，每个规模 n/tʲ，合计 cn(k/t)ʲ；五组都有 k>t，所以越往下总工作越大，深度约 log_t n，末层主导到 n 的 log_t k 次方。五个指数依次约为 1.585、2、1.5、2、1.387，最小的是 (12,6)。子问题个数12最多仍最快，因为每个子问题缩得更小；不能只比较 k。

**题面**（Review-Quiz-2020T2-题目.pdf · Q4 · p.1；公式按原题重排）

> **p.1** “4. Consider the following proposal to improve the $\Theta(n^{\log_2 3})$-time algorithm for multiplying two n-digit integers x and y: Split x (respectively y) into four roughly $\frac n4$-digit integers, and recursively compute multiplications of $\frac n4$-digit integers. Suppose that we can compute product xy by k multiplications of $\frac n4$-digit integers plus O(n)-time for addition. Determine the largest value k that can make an improvement in running time.”

本题已经假设存在这样的乘法分解，不要求发明具体恒等式。要严格快于旧算法，需 log_4 k<log_2 3；把右边乘2得到 log_2 k<log_2 9，故 k<9，最大整数为8。k=8 时为 n^1.5；k=9 则指数等于原算法，只是相同阶，不能称渐近改进。这里的整数乘法是历史题的应用情境，当前 L02 教的是矩阵乘法，不把旧题算法当成新课件漏讲的章节。

**题面**（Final-2021T1-题解.pdf · Part II Q1 · PDF p.3 右栏，印刷 p.6；扫描件，视觉读取）

> **p.3** “1. Determine the asymptotically tight solution for $T(n)=9T(n/3)+\Theta(n^2)$.”

公式按原题重排。第 j 层共有9ʲ项，每项非递归成本与 (n/3ʲ)² 同阶，相乘恰是 n²。共有 Θ(log n) 层，因此总成本 Θ(n²log n)。叶层的 Θ(n²) 小于各内部层总和。这道题要求紧界，单写 O(n²log n) 只给上界，不完整。
